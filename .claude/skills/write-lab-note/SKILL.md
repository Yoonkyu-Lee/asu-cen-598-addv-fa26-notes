# Lab 기록 페이지

**같이 필요한 스킬**
- HTML 규격은 `note-html`. **이 스킬만 읽고 페이지를 만들면 안 된다**
- 시뮬레이션 카드(`.sim`)를 쓰면 `docs/superpowers/specs/2026-09-13-hands-on-primer-design.md`
- 강의 노트를 같이 손대면 `write-note`

**이 스킬만으로 끝나는 것**: 무엇을 쓸지 정하는 것. 절 구조, 경계 확정, 무엇을 싣고 무엇을 안 싣는지

판단이 갈리면 `CLAUDE.md` 가 이긴다.

## 이건 공략이 아니다

같은 `LAB{N}-*.html` 파일명 아래 **장르가 둘**이다. 섞지 않는다.

| | Lab 공략 | **Lab 기록 (이 스킬)** |
|---|---|---|
| 언제 쓰나 | 과제를 받고 **풀기 전** | 과제를 **끝낸 뒤** |
| 독자의 질문 | "이거 풀려면 뭘 봐야 하지" | "그때 우리가 뭘 했고 왜 그랬지" |
| 정렬 | 요구사항 항목 순서 | **Part 순서, 그 안에서 시간 순서** |
| 중심 | 다음 수 | **주어진 것과 얹은 것의 차이** |
| 분량 | 짧다 | **길다. 길어야 한다** |
| 끝나는 곳 | 제출물 체크리스트 | **총정리 위젯** |

`LAB0-tools-tutorial.html` 은 이 스킬이 생기기 전에 만든 것이라 둘 사이에 있다.
**본보기로 삼지 않는다.** 구조는 이 문서를 따른다.

**왜 기록이 필요한가.** Lab 이 성적의 45% 다. 그런데 끝나고 나면 zip 과 PDF 만 남고,
**무엇이 주어진 것이고 무엇을 직접 한 것인지**가 제일 먼저 사라진다. 몇 년 뒤 이력서에
"비동기 FIFO 를 설계했다" 라고 쓸 때 그게 논문 코드를 옮긴 건지 직접 구상한 건지
본인도 모르면 안 된다. **그 경계를 기록하는 것이 이 장르의 존재 이유다.**

## 절 구조

`{N}` 은 Part 번호다. 02~08 을 Part 마다 반복한다. Part 가 셋이면 세 번 돈다.

| 절 | 내용 | 한 번인가 |
|---|---|---|
| 00 | **Overview.** 과제가 시킨 것, 만든 것 한 장 요약, 이 페이지 읽는 법 | 한 번 |
| 01 | **지도.** 이 Lab 이 강의 어디에 붙는가. 선행 노트 링크 | 한 번 |
| `{N}`-1 | **주어진 것.** 백지였나. 주어진 코드는 무엇이고 무엇을 못 하나. 무엇을 해야 하나 | Part 마다 |
| `{N}`-2 | **방향.** 구현 전에 무엇을 근거로 이 설계를 골랐나. 개념, 도해, 인터랙티브 | Part 마다 |
| `{N}`-3 | **구현.** 무엇을 썼나. 무엇이 새로 생겼나. 파일별로 | Part 마다 |
| `{N}`-4 | **검증.** 무엇을 확인하고 싶었고 어떻게 확인했나 | Part 마다 |
| `{N}`-5 | **돌리는 법.** Makefile 과 명령어 | Part 마다 |
| `{N}`-6 | **막힌 곳.** 버그와 어려움. 어떻게 빠져나왔나 | Part 마다 |
| `{N}`-7 | **결과.** 파형과 측정값. 무엇을 시사하나 | Part 마다 |
| 마지막 | **총정리 위젯.** 이것 하나로 Lab 전체가 보이는 것 | 한 번 |

**절 번호는 `.sec-num` 에 두 자리로 적는다.** Part 가 갈리는 것은 `<h2 class="grp">` 로
표시하지 말고 **절 제목에 `Part 1 ·` 접두어**를 붙인다. 목차가 평평해야 뛰어다니기 쉽다.

`data-slide` 를 붙이지 않는다. `reader.js` 를 넣지 않는다. Lab 은 슬라이드가 출처가 아니다.

### 절을 비워두지 않는다

**여섯 절 중 하나라도 "특별히 없었다" 로 끝나면 그 Part 는 아직 정리가 안 된 것이다.**
특히 자주 비는 두 곳:

- **`{N}`-6 막힌 곳이 비었다** → 정말 안 막혔을 리 없다. 커밋 로그와 대화를 다시 본다.
  틀린 예측, 잘못 읽은 스펙, 두 번 짠 코드가 전부 여기 들어간다
- **`{N}`-2 방향이 비었다** → 구현을 먼저 하고 이유를 나중에 붙이면 이렇게 된다.
  "그냥 그렇게 했다" 밖에 안 나오면, 대안이 무엇이었는지부터 적는다

## 01. 주어진 것을 기억에 의존해 적지 않는다

**이 장르에서 제일 틀리기 쉬운 곳이고, 틀리면 페이지 전체가 거짓이 된다.**

`git` 이 단일 출처다. Lab 작업 저장소에서 **출발점을 먼저 커밋해 놓는다.**

```
커밋 1   주어진 것 그대로 (스타터 코드, 또는 참조한 공개 코드)
커밋 2   우리가 얹은 것
```

그러면 `git diff 커밋1 커밋2 --stat` 이 곧 **"무엇을 했는가" 의 답**이다. 기억이 아니라.

**스타터가 없으면 없다는 것을 증명한다.** 어디를 찾아봤는지 적는다.
Lab 1 이 그런 경우였고 `lab1/part1/SOURCE.md` 가 그 기록이다.
강사가 제공한 게 없고 Lab 페이지가 논문을 가리키기만 하면, **그 논문 코드가 출발점**이고
그것을 그대로 커밋한 것이 기준선이 된다.

### 세 칸 표로 적는다

```
| 파일 | 주어진 것 | 바뀐 것 | 왜 |
```

"왜" 칸이 핵심이다. **요구사항 어느 줄 때문에 바뀌었는지**를 적는다.
"SystemVerilog 로 고쳤다" 가 아니라 "요구사항이 `always_ff` 를 명시해서" 다.

### 없어진 파일도 적는다

`fifo1.v` → `async_fifo.sv` 처럼 **이름이 바뀐 것**은 diff 에서 삭제 + 추가로 보인다.
표에서는 한 줄로 묶고 이름이 바뀌었다고 밝힌다. 안 그러면 실제보다 많이 한 것처럼 보인다.

## 02. 무엇을 싣고 무엇을 안 싣는가

**이 저장소는 Public 이고 GitHub Pages 로 서빙된다. 여기 올리는 건 인터넷에 게시하는 것이다.**
Lab 작업 저장소는 Private 이다. **둘을 헷갈리면 사고가 난다.**

| 대상 | 싣나 |
|---|---|
| 공개된 출처의 코드 (논문, 표준 문서, 강의 슬라이드) | **O.** 출처를 밝히고 인용 |
| 우리가 얹은 코드 | **조각만.** 설명에 필요한 몇 줄. 파일 전체를 붙이지 않는다 |
| 우리가 짠 testbench 전체 | **X** |
| 과제 문제지 원문 | **X.** 요구사항 요약으로 쓴다. 문구 자체가 논점일 때만 짧게 인용 |
| 파형 스크린샷 | **O.** 우리 시뮬레이션 결과다 |
| 측정 숫자와 표 | **O** |
| 도해, 설계 근거, FSM, 계산 | **O.** 여기가 이 페이지의 값어치다 |
| 파트너와의 역할 분담 | **X.** 그건 제출 리포트 몫이다 |

**왜 코드 전문을 안 싣나.** 아직 진행 중인 과목의 채점 대상이다. 전문을 게시하면
다음 학기 학생이 그대로 쓴다. 그리고 2 인 1 조 과제라 **파트너의 코드까지 같이 게시하는 것**이
된다. 파트너에게 그 권한을 받은 적이 없다.

**그래서 무엇이 남나.** 이해를 나르는 것 전부가 남는다. 도해, 왜 그 구조인지, FSM 이 무슨
상태를 왜 갖는지, 깊이를 어떻게 계산했는지, 측정값이 무엇을 말하는지. **코드는 이해의
결과물이지 이해 자체가 아니다.** 몇 년 뒤 이 페이지를 읽고 Private 저장소를 열면 코드가 읽힌다.
그 순서가 맞다.

**사용자가 전문을 싣기로 결정하면 그 결정을 따른다.** 다만 위 위험을 먼저 알린다.
`CLAUDE.md` 의 슬라이드 커밋 결정과 같은 성격이고, **한 번 내려진 결정을 조용히 뒤집지 않는다.**

## 03. 방향 절이 이 페이지를 학습 자료로 만든다

`{N}`-2 가 없으면 이 페이지는 그냥 변경 이력이다.

- **대안을 먼저 적는다.** 무엇과 무엇 중에 골랐나. 안 고른 쪽이 왜 졌나
- **그때 몰랐던 것을 숨기지 않는다.** 나중에 알고 보니 전제가 틀렸으면 그것도 기록이다
- **숫자로 정한 것은 계산 과정을 전부 적는다.** 답만 적으면 몇 년 뒤 재현이 안 된다
- 도해와 인터랙티브를 **여기에 몰아 넣는다.** 구현 절이 아니라 방향 절이다

### 예측과 측정을 나란히 놓는다

**이 장르의 시그니처다.** 설계 전에 예측한 값이 있으면 적고, 측정값을 옆에 놓는다.
**틀렸으면 틀렸다고 적는다.** 맞춘 것보다 틀린 것이 몇 배 값지다.

```
| | 예측 | 측정 | 차이의 이유 |
```

측정 없이 "~일 것이다" 만 적힌 숫자는 **적지 않는다.** 이 저장소의 다른 규칙과 같다.
근거 없는 주장은 사용자가 바로 잡아낸다.

## 04. 결과 절: 파형은 붙이는 게 아니라 읽는 것이다

스크린샷만 붙이면 값이 없다. 파형 하나마다 셋을 붙인다.

1. **어디를 보라.** 신호 이름과 대략의 시각. "여기" 라고만 쓰지 않는다
2. **그 순간 회로 안에서 무슨 일이 일어났나.** 회로도나 코드 조각과 짝지어 쓴다
3. **그래서 무엇이 확인됐나.** 요구사항 어느 줄이 이걸로 증명되나

**주석은 이미지 위에 구우지 않는다.** 파형 PNG 를 `figure` 에 넣고 **설명은 HTML 로 옆에 둔다.**
그래야 이중 언어가 되고 다크모드에서 안 깨지고 나중에 고칠 수 있다.
이미지에 구운 글씨는 그 셋이 다 안 된다.

**RTL 시각화는 파형과 짝을 이룰 때만 값이 있다.** 블록도만 따로 그리면 방향 절과 겹친다.
결과 절의 블록도는 **파형에 보이는 신호가 회로 어디를 지나는지** 를 보여주는 것이어야 한다.

## 05. 인터랙티브: 어느 장치를 쓰나

세 장치가 있고 **용도가 다르다.** 규격은 `note-html` 이 단일 출처다.

| 장치 | 이 장르에서의 쓰임 | 어느 절 |
|---|---|---|
| `.sim` | "이 코드가 이 회로이고 이렇게 돈다" 를 반 클럭씩 | 방향, 결과 |
| `.anim` | 여러 프레임에 걸친 시나리오를 밟아본다 | 방향, 결과 |
| `.play` | 독자가 값을 넣고 결과를 본다 (계산기, 탐색기) | 방향, 총정리 |

### 축소 모형으로 만든다

**실물 크기를 넣으려 하지 않는다.** `.sim` 의 회로 노드는 격자 위 박스라
깊이 40 짜리 메모리를 그릴 수 없고, 값 계산이 `1 << bits` 라 폭도 제한된다.

**깊이 2~4, 폭 2~3 비트로 줄인다.** 그리고 **줄였다는 것을 카드에 밝힌다.**
줄여도 보여주려는 동작이 살아 있으면 그게 맞는 모형이다. 살지 않으면 그 개념은
`.sim` 으로 보여줄 것이 아니다. **도해로 간다.**

Lab 1 이 실제 사례다. 실물은 깊이 40 · 64 지만 동기화기 지연과 포인터 비교는
깊이 4 에서 그대로 보인다. 반면 40 칸이 차오르는 것 자체가 논점인 곳은 `.sim` 이
아니라 **점유량 그래프**여야 한다.

### 이미 있는 도구를 다시 만들지 않는다

강의 노트가 같은 개념의 인터랙티브를 이미 갖고 있으면 **링크한다.**
L05 에 깊이 4 짜리 FIFO 도구가 있는데 Lab 기록에서 또 만들면 둘이 갈라진다.
**Lab 페이지는 강의 노트가 안 다루는 것만 만든다.** 이 Lab 에서 실제로 부딪힌 것.

## 06. 총정리 위젯

마지막 절 하나를 **"이것만 있으면 Lab 전체가 보이는 것"** 에 쓴다.

기준: **Part 를 가로지르는가.** 한 Part 안에서만 도는 것은 그 Part 의 절에 둔다.
총정리 자리에 올 수 있는 형태:

- **구조 탐색기.** 모듈을 누르면 그게 무엇인지 / 주어진 것인지 우리가 쓴 것인지 /
  어느 테스트가 덮는지 / 어느 파형에 나오는지를 한꺼번에 보여준다
- **비교판.** 두 구현을 같은 축에 놓고 어디가 갈리는지
- **경로 추적.** 데이터 한 개가 입력에서 출력까지 어디를 지나는지

**안 만드는 것.** 요약 표만 있는 것. 그건 위젯이 아니라 표다. 표는 표로 둔다.

위젯이 안 나오면 **억지로 만들지 않는다.** 표와 도해로 끝내고 다음 Lab 에서 다시 본다.
목적은 위젯을 채우는 게 아니라 Lab 전체가 한눈에 보이게 하는 것이다.

## 07. 검증

```bash
node scripts/verify.mjs   notes/LAB{N}-{kebab}.html    # exit 0 이어야 통과
node scripts/langcheck.mjs notes/LAB{N}-{kebab}.html
node scripts/simcheck.mjs notes/LAB{N}-{kebab}.html    # .sim 이 있으면
node scripts/animshot.mjs notes/LAB{N}-{kebab}.html    # .anim 이 있으면
```

`readercheck.mjs` 는 **안 돌린다.** 리더가 없다.

**`verify.mjs` 에 Lab 전용 검사가 하나 있다.** 강의 노트가 `LAB{N} Task {번호}` 를
언급하면 Lab 페이지에 `data-task="{번호}"` 가 있는지 대조한다. Task 로 나뉘지 않는
Lab (Part 로 나뉘는 경우) 은 `data-task` 를 안 쓰면 되고, 그러면 이 검사가 조용히 통과한다.
**`write-note` 스킬에 "`LAB*.html` 도 보도록 스크립트를 고친다" 라고 적혀 있는데
이미 고쳐져 있다.** 그 줄은 낡았다.

**도해 스크린샷을 전부 눈으로 연다.** 이 장르는 도해가 많아서 특히 새기 쉽다.

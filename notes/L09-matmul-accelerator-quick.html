왜 전용 하드웨어인가

Why dedicated hardware

슬라이드 4쪽의 정의는 특정 일을 hardware 에 offload 해서 accelerate 하는 것이고, 목적은 lower power, lower time, lower energy. 5쪽이 칩을 CPU, GPU, FPGA, ASIC 순으로 늘어놓는다. 이 순서로 유연성을 내주고 효율을 얻는다. 6쪽이 CPU 가 왜 비효율적인지를 숫자로 보인다(45 nm, 0.9 V, Horowitz ISSCC 2014).

Slide 4 defines it as offloading a task to hardware to accelerate it, for lower power, lower time, lower energy. Slide 5 lines chips up as CPU, GPU, FPGA, ASIC, trading flexibility for efficiency in that order. Slide 6 shows in numbers why a CPU is inefficient (45 nm, 0.9 V, Horowitz ISSCC 2014).

그림 읽기Reading the picture

로그 축이라 눈금 한 칸이 10 배다. 초록이 계산(add 8/32 bit 0.03/0.1 pJ, mult 8/32 bit 0.2/3.1 pJ), 주황이 명령어마다의 부대 비용(register file 6 pJ, I-cache 25 pJ), 회색이 메모리(캐시 8 KB 10 pJ, 32 KB 20 pJ, 1 MB 100 pJ, DRAM 1.3–2.6 nJ). 32 bit 덧셈 대비 I-cache 는 250 배, DRAM 은 13,000–26,000 배. 슬라이드의 Control 은 숫자가 없어 빠졌다. 8 bit 곱셈이 32 bit 보다 약 15 배 싸다.

Log axis, one gridline per factor of ten. Green is arithmetic (add 8/32 bit 0.03/0.1 pJ, mult 8/32 bit 0.2/3.1 pJ), amber is per-instruction overhead (register file 6 pJ, I-cache 25 pJ), grey is memory (8 KB 10 pJ, 32 KB 20 pJ, 1 MB 100 pJ, DRAM 1.3 to 2.6 nJ). Against a 32-bit add the I-cache costs 250× and DRAM 13,000 to 26,000×. The slide's Control has no number, so it's left out. An 8-bit multiply is about 15× cheaper than 32-bit.

슬라이드 7쪽(Dally 외, CACM 2020)의 가속 원천 다섯: reduced overhead (fetch, decode 제거), specialization (domain specific data types), parallelism (many PEs), optimized memory, optimized communication.

Slide 7's five sources of acceleration (Dally et al., CACM 2020): reduced overhead (no fetch, decode), specialization (domain specific data types), parallelism (many PEs), optimized memory and optimized communication.

Power 와 energy 는 다르다. energy = power × time. 순간 전력을 더 먹어도 빨리 끝내면 총 에너지는 작을 수 있다. 슬라이드 4쪽이 둘을 따로 적은 이유다.

Power and energy differ. Energy = power × time, so drawing more power but finishing sooner can still mean less energy. That's why slide 4 lists them separately.

PE 와 systolic array

PEs and systolic arrays

PE (Processing Element) 는 배열 안에서 반복되는 계산 칸이다. 슬라이드 10쪽이 크기 사다리를 준다. MAC → Dot Product Unit → MVM → MMM. 11쪽에서 TPU 는 MMM 격자(64K per cycle), Brainwave 는 MVM (Tile Engine), GPU 는 4×4 Tensor Core (D = A × B + C, HMMA 명령어)를 골랐다. PE 의 크기는 정해져 있지 않다.

A PE (Processing Element) is one repeated compute cell. Slide 10 gives a size ladder: MAC → Dot Product Unit → MVM → MMM. On slide 11 the TPU picks an MMM grid (64K per cycle), Brainwave an MVM (Tile Engine), and GPUs a 4×4 Tensor Core (D = A × B + C, the HMMA instruction). A PE has no fixed size.

슬라이드 12쪽: A systolic array is a network of processors that rhythmically compute and pass data through the system. 그리고 데이터가 들어올 때 한 번이 아니라 배열을 지나며 계속 reused 된다.

Slide 12: A systolic array is a network of processors that rhythmically compute and pass data through the system, and data is reused as it moves through, not just used once on entry.

그림 읽기Reading the picture

왼쪽(12쪽)은 Memory 에서 나온 데이터가 PE 를 한 줄로 지나 다시 Memory 로 가는 1D daisy chain. 오른쪽(13쪽)은 4 × 4 = 16 개 PE 의 2D mesh 로, 위와 왼쪽 가장자리로만 들어와 오른쪽과 아래 이웃으로만 넘긴다. 13쪽의 성질 다섯: 가장자리로만 출입, 안쪽은 이웃만, 메모리 효율, 대칭적인 dataflow, no global wires. 배선이 옆 칸까지만 가니 배열을 키워도 가장 긴 경로가 PE 하나 안에 머문다.

Left (slide 12): a 1D daisy chain, data from Memory passing through PEs in a line and back to Memory. Right (slide 13): a 2D mesh of 4 × 4 = 16 PEs, entering only at the top and left edges and passing only right and down. Slide 13's five properties: in and out at the edges only, neighbours only inside, efficient memory use, symmetric dataflow, no global wires. With wires reaching only the next cell, a bigger array keeps its longest path inside one PE.

PE 하나가 하는 일은 둘이다(29–30쪽). MAC, 즉 Y = A*B + Y_prev. 그리고 받은 a 를 오른쪽, b 를 아래로 register 에 한 사이클 담았다가 넘기기.

One PE does two things (slides 29 and 30): a MAC, Y = A*B + Y_prev, and passing the received a right and b down after holding each in a register for one cycle.

3 × 3 을 한 사이클씩

3 × 3, cycle by cycle

슬라이드 14–28쪽이 예제 하나다. PE(i,j) 하나가 결과 c i,j 하나를 끝까지 누적한다(Each processor accumulates one element of the product). 첨자는 0 부터. A 의 행 i 는 i 칸, B 의 열 j 는 j 칸 뒤에 줄을 선다(Alignments in time).

Slides 14 to 28 are one example. Each PE(i,j) accumulates one result c i,j to the end (each processor accumulates one element of the product). Indices start at 0. Row i of A queues i slots back and column j of B j slots up (Alignments in time).

그림 읽기Reading the picture

a i,k 는 행 i 가 i 늦게 출발하고 k 번째라 PE(i,0) 에 T = i + k + 1, 오른쪽으로 j 칸 걸어 T = i + j + k + 1. b k,j 도 같은 식으로 T = j + k + 1 + i. 두 값이 PE(i,j) 에서 같은 사이클에 만난다. 칸의 숫자는 k = 0, 1, 2 를 넣은 값이고, PE(i,j) 는 T = i + j + 3 에 완성된다. 마지막 PE(2,2) 는 T = 7 = 3N − 2, 빼내기 3 사이클을 더해 10 = 4N − 2.

a i,k: row i starts i late and it's k-th, so it reaches PE(i,0) at T = i + k + 1 and walks j cells right to T = i + j + k + 1. b k,j likewise arrives at T = j + k + 1 + i. They meet in PE(i,j) in the same cycle. Cell numbers are k = 0, 1, 2 plugged in; PE(i,j) completes at T = i + j + 3. The last, PE(2,2), at T = 7 = 3N − 2; three cycles of shifting out make 10 = 4N − 2.

그림 읽기Reading the picture

바깥 줄의 a i,k 는 배열에서 i + k − T 칸, b k,j 는 j + k − T 칸 떨어져 있다. PE 안의 파란 굵은 줄이 이번 사이클의 항(k = T − 1 − i − j)이다. 사이클별 MAC 수 1, 3, 6, 7, 6, 3, 1 의 합이 27 = 3³. 결과 컷의 C0–C8 은 행 우선 번호 C(3i + j) = c i,j. T = 8, 9, 10 에 열 2, 1, 0 순으로 오른쪽 밖으로 나간다.

A queued a i,k sits i + k − T slots from the array, b k,j sits j + k − T. The bold blue line in a PE is this cycle's term (k = T − 1 − i − j). MACs per cycle, 1, 3, 6, 7, 6, 3, 1, sum to 27 = 3³. In the results frame C0 to C8 number row first, C(3i + j) = c i,j. At T = 8, 9, 10 columns 2, 1, 0 leave to the right in that order.

슬라이드 20–25쪽의 PE(1,0) 칸 a1,2*a2,0 은 오타다. a1,2*b2,0 이 맞다. 그리고 첨자는 9쪽 DNN 예만 1 부터, 14쪽부터는 0 부터다.

The PE(1,0) box on slides 20 to 25 reads a1,2*a2,0, a typo for a1,2*b2,0. Also, only slide 9's DNN example counts from 1; from slide 14 on it's 0.

그림 읽기Reading the picture

위 줄은 가장자리로 들어온 A, B 원소 수 2, 4, 6, 4, 2 (T = 3 의 6 = 2N 이 peak, 합 18 = 2N²). 가운데는 MAC 1, 3, 6, 7, 6, 3, 1 (합 27 = N³). 아래는 T = 8, 9, 10 에 결과 3 개씩 (= N, 합 9). 계산 7 = 3N − 2, 빼내기 3 = N, 합 10 = 4N − 2.

Top: A and B elements entering at the edges, 2, 4, 6, 4, 2 (6 = 2N at T = 3 is the peak; 18 = 2N² in total). Middle: MACs 1, 3, 6, 7, 6, 3, 1 (27 = N³). Bottom: three results at each of T = 8, 9, 10 (= N; 9 in total). Compute 7 = 3N − 2, shift out 3 = N, together 10 = 4N − 2.

3N − 2 는 계산이 끝난 시점, 4N − 2 는 결과가 다 나온 시점이다. MAC 가 여러 사이클짜리면 그만큼 더한다. 그리고 31쪽의 "element" 는 숫자 하나지만 RAM 에서는 주소 하나에 숫자 N 개가 들어간다(슬라이드 1쪽 발표자 노트).

3N − 2 is when compute ends; 4N − 2 is when every result is out. Add the MAC's latency if it takes several cycles. And slide 31's "element" is one number, while in RAM one address holds N numbers (speaker notes on slide 1).

Verilog 로 짤 때

Building it in Verilog

슬라이드 35–40쪽이 Lab 3 의 블록도를 한 부품씩 쌓는다. matmul 안은 PE 격자, Systolic data setup circuits, Output data interface. 바깥에 dual-port RAM 셋(A, B 입력, C 출력)과 State Machine(Start, Done), 그리고 전체를 감싼 Testbench.

Slides 35 to 40 stack up Lab 3's block diagram one part at a time. Inside the matmul: the PE grid, systolic data setup circuits and an output data interface. Outside it: three dual-port RAMs (A and B in, C out), a state machine (Start, Done), and a testbench around everything.

그림 읽기Reading the picture

port 1 은 matmul 쪽이다. A, B 는 addr 를 보내고 data 를 받고(읽기만), C 로는 addr 와 data 를 둘 다 보낸다(쓰기). 안 쓰는 입력은 tie off(상수에 묶기). port 2 는 testbench 쪽 addr_ext, wdata_ext, rdata_ext, we_ext. 분홍 목록이 40쪽의 여섯 단계이고, 1 과 5 는 port 2, 3 과 4 는 start 와 done 으로 한다.

Port 1 faces the matmul: A and B get addr and return data (read only); C receives both addr and data (written). Unused inputs are tied off to constants. Port 2 faces the testbench: addr_ext, wdata_ext, rdata_ext, we_ext. The pink list is slide 40's six steps; 1 and 5 go through port 2, 3 and 4 use start and done.

그림 읽기Reading the picture

RAM 한 주소에서 숫자 N 개가 동시에 나오므로, 갈래마다 register 를 0, 1, 2, 3 개 두어 계단을 만든다(+0 … +3 사이클). 한쪽에 N(N − 1)/2 = 6 개, 양쪽 12 개. 그래서 RAM 의 주소 k 에는 A 의 열 k(lane 별로는 행을 따라가니 row major)와 B 의 행 k(lane 별로 열을 따라가니 column major)가 들어간다(43쪽).

One RAM address delivers N numbers at once, so each branch gets 0, 1, 2 or 3 registers to build the staircase (+0 to +3 cycles): N(N − 1)/2 = 6 per side, 12 in all. That's why address k holds column k of A (row major per lane, walking along a row) and row k of B (column major per lane) on slide 43.

결과를 빼내는 그림이 두 가지다. 26–28쪽은 PE 를 타고 오른쪽으로, 42쪽은 열마다 모아 아래 Shift Register 로. 슬라이드는 둘의 관계를 말하지 않는다. Lab 3 에서는 과제 문서의 출력 인터페이스를 따른다.

There are two pictures of getting results out: slides 26 to 28 shift them right through the PEs, slide 42 gathers each column into a Shift Register at the bottom. The slides don't say how they relate. In Lab 3, follow the assignment's output interface.

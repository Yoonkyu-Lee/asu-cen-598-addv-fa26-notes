FIFO 란 무엇인가

What a FIFO is

슬라이드 4쪽의 정의 그대로다. "A First-In, First-Out (FIFO) buffer that temporarily stores data in the order it was received."

두 가지를 동시에 말하고 있다. 임시로 저장한다는 것, 그리고 받은 순서를 지킨다는 것.

Straight from slide 4: "A First-In, First-Out (FIFO) buffer that temporarily stores data in the order it was received."

It says two things at once: that it stores temporarily, and that it preserves the order it received things in.

용어 뜯어보기 · FIFOUnpacking the jargon · FIFO
풀네임First-In, First-Out
한 줄먼저 들어온 데이터가 먼저 나오는 버퍼. 소프트웨어에서 queue 라고 부르는 것과 같은 개념인데, 하드웨어 쪽에서는 거의 항상 FIFO 라고 쓴다

슬라이드 4쪽이 비유로 시작한다. 노트북 공장이 학기당 한 번 1800 대를 보내고 매장은 하루 10 대씩 판다. 그 사이에 창고가 있다.

Slide 4 opens with an analogy: a laptop factory ships 1800 units once a semester while the shop sells ten a day. A warehouse sits between them.

비유가 잘 골라진 이유는 숫자가 실제로 맞기 때문이다. 한 학기를 180 일이라고 치면 1800 대를 다 판다. 평균은 맞고 순간만 안 맞는 상황이고, 그게 정확히 FIFO 가 쓸모 있는 조건이다.

The analogy is well chosen because the numbers actually work out: at ten a day, 180 days clears 1800 units. The averages match and only the instants disagree, which is exactly the condition under which a FIFO helps.

FIFO 는 속도를 바꾸지 않는다. 이걸 놓치면 설계 전체가 틀어진다. 평균 생산량이 평균 소비량보다 크면, FIFO 를 아무리 깊게 파도 언젠가 반드시 가득 찬다. 깊이를 늘리는 것은 넘치는 시점을 미루는 것이지 막는 게 아니다.

반대도 같다. 평균 소비량이 더 크면 언젠가 반드시 마른다. FIFO 가 흡수하는 것은 평균의 차이가 아니라 순간의 들쭉날쭉함(burst)이다.

그래서 실무에서 "FIFO 가 자꾸 넘쳐요" 는 대개 FIFO 가 얕아서가 아니라 상류가 너무 빨라서다. 깊이를 두 배로 늘리기 전에 평균이 맞는지부터 본다.

A FIFO does not change rates. Miss this and the whole design goes wrong. If average production exceeds average consumption, no depth prevents it filling up eventually. Adding depth postpones the overflow; it does not stop it.

The reverse holds too: if consumption is faster on average, it will eventually run dry. What a FIFO absorbs is burstiness, not a difference in averages.

So "our FIFO keeps overflowing" usually means the upstream is too fast, not that the FIFO is too shallow. Check that the averages balance before doubling the depth.

In a lineWidth is how many bits fit in one slot; depth is how many slots there are. The slide marks them with a horizontal and a vertical arrow
Why bothThey are decided by different things. Width is the size of one datum, set by whatever is upstream; depth is how much you can tolerate, set by the burst size

Easily confusedDepth is not always the number of items you can hold. Some designs deliberately leave one slot empty. This one decides full with a wrap bit, so it uses every slot

full 과 empty 는 입력이 아니라 출력이다. 그림에서 초록색으로 칠한 이유가 이것이다. FIFO 가 바깥에 알려주는 신호이고, 바깥이 그걸 보고 자기 요청을 접어야 한다.

그리고 쓰는 쪽이 볼 것과 읽는 쪽이 볼 것이 다르다. 쓰는 쪽은 full 만 보면 되고 empty 는 자기와 상관없다. 읽는 쪽은 그 반대다. 이걸 뒤집어 보면 가득 찬 FIFO 에 쓰거나 빈 FIFO 를 읽는다.

다만 이 설계는 11 절에서 보듯 FIFO 안쪽에서도 한 번 더 막아준다. 그게 없는 FIFO 도 세상에 많으므로, 남의 IP 를 쓸 때는 막아주는지를 문서에서 확인해야 한다.

full and empty are outputs, not inputs. That is why they are green in the figure. The FIFO tells the outside world, and the outside world is expected to hold back its own request.

And each side watches a different one. The writer only needs full; empty is none of its business, and the reverse for the reader. Swap them and you write into a full FIFO or read an empty one.

This particular design also blocks the request internally, as §11 shows. Plenty of FIFOs do not, so when you instance somebody else's IP, check the documentation for whether it does.

포트 이름에 wr_ 와 rd_ 접두사가 붙은 것도 그냥 스타일이 아니다. 동기 FIFO 에서는 wr_clk 과 rd_clk 이 같은 신호인데도 이름을 갈라놨다. 13 절에서 둘이 진짜로 갈라질 때 포트 목록을 안 고쳐도 되게 하려는 것이다.

The wr_ and rd_ prefixes are not just style either. In a synchronous FIFO wr_clk and rd_clk are the same signal, yet the names are already split, so that when they genuinely diverge in §13 the port list does not have to change.

현장 감각On the job

센서가 100 kHz 로 꾸준히 샘플을 내놓고, 프로세서는 그걸 읽어서 처리하는데 가끔 인터럽트 때문에 최대 200 마이크로초 동안 못 읽는다. 평균 처리 속도는 충분하다. FIFO 를 얼마나 깊게 잡아야 하나? 그리고 이 판단에서 진짜 위험한 가정은 무엇인가?

A sensor produces samples steadily at 100 kHz, and the processor reads and handles them but can be blocked by interrupts for up to 200 microseconds. Average throughput is more than enough. How deep should the FIFO be, and what is the genuinely dangerous assumption in this calculation?

생각해본 뒤 펼치기Think first, then open

막힌 동안 쌓이는 양은 100 kHz × 200 µs = 20 샘플이다. 그러니 최소 20 칸이고, 주소를 2 의 거듭제곱으로 잡는 게 편하니 32 칸으로 간다. 15 절에서 보듯 gray code 가 2 의 거듭제곱 깊이를 전제하므로 이 반올림은 그냥 편의가 아니다.

진짜 위험한 가정은 "최대 200 마이크로초" 라는 숫자를 어디서 얻었는가다. 측정해서 얻은 값이면 그건 관측한 최대치이지 실제 최대치가 아니다. 인터럽트가 겹치는 최악의 경우를 관측하지 못했을 수 있다. 그래서 실무에서는 계산값에 여유를 붙이고, 넘쳤을 때 조용히 지나가지 않게 만든다.

그 두 번째가 더 중요하다. overflow 를 감지해서 알리는 신호나 카운터를 둔다. 2 강에서 assertion 의 예시로 나왔던 문장이 정확히 이것이다. "FIFO 는 overflow 하면 안 된다." 깊이를 맞히는 것보다 틀렸을 때 알아채는 것이 설계다.

The backlog is 100 kHz × 200 µs = 20 samples, so at least 20 slots, rounded to 32 because a power-of-two address is convenient. And as §15 shows, gray code assumes a power-of-two depth, so that rounding is more than convenience.

The dangerous assumption is where the "at most 200 microseconds" came from. If it was measured, it is the largest value observed, not the largest value possible; the worst overlap of interrupts may simply never have been seen. So real designs add margin to the number and make sure an overflow cannot pass silently.

The second half matters more. Add a signal or a counter that reports the overflow. This is exactly the sentence Lecture 2 used as its assertion example: "a FIFO must not overflow." Getting the depth right is guesswork; noticing when you got it wrong is design.

full 과 empty 를 가르는 한 비트

The one bit that separates them

문제를 정확히 놓자. 원형 버퍼에서 두 포인터가 같은 주소를 가리키는 상황은 두 번 온다.

State the problem precisely. In a circular buffer, the pointers land on the same address twice.

하나는 아무것도 안 넣었을 때. 쓰는 쪽이 한 번도 안 움직였으니 둘이 출발점에 같이 있다.

다른 하나는 쓰는 쪽이 한 바퀴 돌아서 읽는 쪽을 따라잡았을 때. 깊이만큼 썼는데 아무도 안 읽었으면 정확히 제자리로 돌아온다.

Once when nothing has been written, with both still at the start.

Once when the writer has gone all the way round and caught up, having written exactly depth items that nobody read.

주소만 비교하면 이 둘이 완전히 똑같아 보인다. 그래서 주소만으로는 판정 자체가 불가능하다. 식을 잘못 세운 게 아니라 정보가 모자란 것이다.

Compare addresses alone and the two are indistinguishable. No formula can separate them, because the information is not there to begin with.

해법은 포인터에 "한 바퀴를 돌았다" 는 기록을 남기는 것이다. 주소가 ADDR_WIDTH 비트면 포인터는 ADDR_WIDTH+1 비트로 두고, 맨 위 한 비트는 주소로 쓰지 않는다. 주소부가 한 바퀴 돌아 올림이 발생할 때마다 이 비트가 저절로 뒤집힌다.

깊이가 4 면 ADDR_WIDTH 가 2 이고 포인터는 3 비트다. 앞 절 표의 000 과 100 이 이것이다.

The fix is to let the pointer record that it has been round. If the address is ADDR_WIDTH bits, make the pointer ADDR_WIDTH+1 bits and never use the top bit as an address. Every time the address part wraps and carries out, that bit flips by itself.

With depth four, ADDR_WIDTH is 2 and the pointer is 3 bits. That is the 000 and 100 in the previous table.

empty: 두 포인터가 wrap bit 까지 완전히 같다. 같은 자리, 같은 바퀴.

full: 주소부는 같은데 wrap bit 가 다르다. 같은 자리인데 쓰는 쪽이 정확히 한 바퀴 앞서 있다.

empty: the pointers are identical including the wrap bit. Same slot, same lap.

full: the address bits match and the wrap bits differ. Same slot, and the writer is exactly one lap ahead.

현장 감각On the job

깊이 64, width 16 인 FIFO 를 만든다. ADDR_WIDTH 는 몇이고 포인터는 몇 비트인가? 그리고 어느 순간 파형을 떠 보니 wr_ptr = 1000101, rd_ptr = 0000101 이다. 이 FIFO 는 지금 어떤 상태이고, 안에 몇 개가 들어 있나?

You are building a FIFO of depth 64 and width 16. What is ADDR_WIDTH, and how wide is the pointer? Then a waveform shows wr_ptr = 1000101 and rd_ptr = 0000101. What state is it in, and how many items does it hold?

생각해본 뒤 펼치기Think first, then open

64 = 26 이므로 ADDR_WIDTH 는 6 이고 포인터는 7 비트다. 슬라이드 33쪽 코드의 parameter 기본값이 정확히 이 조합이다.

두 값을 쪼개보면 주소부가 000101 로 같고 wrap bit 가 1 과 0 으로 다르다. 판정식 그대로 full = 1 이다.

그리고 들어 있는 개수는 64 개다. 가득 찼으니까. 여기가 재미있는 지점인데, 개수를 세는 카운터가 없어도 개수를 알 수 있다. 두 포인터를 7 비트 뺄셈하면 1000101 - 0000101 = 1000000 즉 64 다. 포인터 차이가 곧 점유량이고, wrap bit 를 포함해서 빼면 한 바퀴까지 제대로 세어진다.

이게 wrap bit 방식의 숨은 이득이다. almost_full 이나 almost_empty 같은 신호가 필요할 때 카운터를 새로 안 만들어도 된다. 이 강의는 거기까지 안 가지만, Lab 1 에 그런 요구가 붙으면 여기를 쓴다.

64 = 26, so ADDR_WIDTH is 6 and the pointer is 7 bits. Exactly the parameter defaults in the slide 33 code.

Splitting the two values, the address parts are both 000101 and the wrap bits are 1 and 0. By the rule, full = 1.

And it holds 64 items, since it is full. Here is the interesting part: you can know the occupancy without a counter. Subtract the pointers as 7-bit numbers: 1000101 - 0000101 = 1000000, which is 64. The pointer difference is the occupancy, and including the wrap bit makes it count correctly all the way round.

That is the hidden benefit of the wrap-bit scheme: signals like almost_full or almost_empty need no new counter. This lecture does not go there, but if Lab 1 asks for one, this is where it comes from.

먼저 눈에 띄는 것. 파라미터 셋이 서로 독립이 아니다. ADDR_WIDTH 는 FIFO_DEPTH 에서 나오는 값이라 둘을 따로 주면 어긋날 수 있다. 슬라이드는 기본값을 맞춰놨을 뿐 검사는 안 한다. 실무 코드라면 ADDR_WIDTH = $clog2(FIFO_DEPTH) 로 유도하거나 assertion 으로 묶는다.

The first thing to notice: the three parameters are not independent. ADDR_WIDTH follows from FIFO_DEPTH, so passing them separately lets them disagree. The slide simply picks consistent defaults and checks nothing. Production code would derive it, ADDR_WIDTH = $clog2(FIFO_DEPTH), or tie them together with an assertion.

읽기가 조합 논리다. assign r_data = mem[r_addr]; 에는 클럭이 없다. r_addr 이 바뀌면 같은 사이클에 r_data 가 따라 바뀐다.

이걸 놓치면 타이밍 계산이 틀린다. 메모리를 읽고 나서 뒤에 조합 논리가 더 붙으면 그게 전부 한 클럭 안에 들어가야 한다. 깊은 메모리에서 이 경로가 critical path 가 되는 일이 흔하다.

그래서 실제 설계에는 읽기를 register 로 한 단 끊는 선택지가 있다. 대신 읽기 요청과 데이터 사이에 한 클럭 지연이 생기고 바깥 프로토콜이 바뀐다. 이 강의의 FIFO 는 지연 없는 쪽을 골랐다. 어느 쪽이 맞다가 아니라 무엇을 주고 무엇을 받느냐의 문제다.

The read is combinational. There is no clock in assign r_data = mem[r_addr];. Change r_addr and r_data follows in the same cycle.

Miss this and your timing is wrong. Any combinational logic after the memory read has to fit in the same clock period, and on a deep memory this path is a common critical path.

Real designs therefore have the option of registering the read output, at the cost of a one-cycle gap between request and data, which changes the external protocol. This FIFO chose the no-latency side. Not a matter of right and wrong but of what you trade for what.

3 강이 여기서 일한다. 3 강 16 절의 결정표를 그대로 적용하면 이 파일이 나온다. 단순 조합 논리는 assign 이라 읽기가 assign 이고, 클럭 엣지에서 값을 잡는 것은 always_ff 와 <= 라 쓰기가 그 모양이다. 슬라이드가 always_ff 대신 always 를 쓴 것은 Verilog 스타일을 유지한 것이고, 3 강 기준으로는 always_ff 가 낫다.

Lecture 3 shows up here. Apply Lecture 3 §16's decision table and this file falls out. Simple combinational takes assign, hence the read; capturing on a clock edge takes always_ff with <=, hence the write. The slide's plain always instead of always_ff keeps to Verilog style; by Lecture 3's rule always_ff is better.

두 번째 덩어리가 이 설계에서 가장 값싸고 가장 중요한 방어다. 슬라이드 주석이 "A request is accepted only if the current FIFO state allows it" 이라고 적어놨다.

The second part is the cheapest and most important defence in the design. The slide comments it as "A request is accepted only if the current FIFO state allows it."

full 인데 wr_ena 가 들어오면 wr_do 가 0 이 되어 포인터가 안 움직인다. 쓰기 요청이 조용히 버려진다. 이게 없으면 아직 안 읽은 데이터를 덮어쓰고, 게다가 포인터가 한 칸 앞서 나가서 FIFO 가 "비었다" 고 착각한다. 한 번의 실수가 데이터 손실과 상태 붕괴 둘 다를 일으킨다.

If full is high when wr_ena arrives, wr_do is 0 and the pointer does not move. The request is silently dropped. Without it, you overwrite unread data and the pointer runs one slot ahead, so the FIFO then believes it is empty. One mistake causing both data loss and a corrupted state.

슬라이드는 증가량을 더 길게 쓴다. wr_ptr + (wr_do ? {{ADDR_WIDTH{1'b0}}, 1'b1} : {(ADDR_WIDTH+1){1'b0}}) 형태다. 폭을 명시적으로 맞춘 방어적 스타일이고 결과는 위의 1'b1 과 같다. 이 노트에서는 읽기 쉬운 쪽을 썼다.

슬라이드가 굳이 저렇게 쓴 이유는 짐작이 간다. 삼항 연산자의 두 갈래 폭이 다르면 헷갈리기 쉽고, 폭을 손으로 적어두면 나중에 ADDR_WIDTH 를 바꿔도 의도가 코드에 남는다. 다만 이 강의가 그 이유를 설명하지는 않는다.

The slide writes the increment the long way, as wr_ptr + (wr_do ? {{ADDR_WIDTH{1'b0}}, 1'b1} : {(ADDR_WIDTH+1){1'b0}}). That is defensive style making the widths explicit, and it evaluates the same as the 1'b1 above. These notes use the readable form.

You can guess why the slide does it: mismatched widths in the two arms of a ternary are easy to get wrong, and spelling them out means the intent survives in the code when ADDR_WIDTH later changes. The lecture itself never explains the choice.

비교 대상이 ptr 이 아니라 ptr_next 다. 그냥 스타일이 아니라 필수다.

플래그도 다음 절에서 보듯 register 다. 즉 지금 계산한 값이 다음 클럭에 출력으로 나간다. 현재 포인터로 판정하면 플래그가 한 사이클 늦고, 그 한 사이클 사이에 가득 찬 FIFO 에 한 번 더 쓰게 된다.

이 버그가 고약한 이유는 경계에서만 나타나기 때문이다. 절반쯤 찬 상태로 오래 돌리는 테스트에서는 절대 안 걸린다. 가득 채웠다가 비우는 테스트를 일부러 써야 잡힌다. Lab 1 testbench 를 쓸 때 이걸 염두에 둘 것.

The comparison uses ptr_next, not ptr. Not a style choice but a requirement.

The flags are registers too, as the next section shows, so what you compute now appears on the output at the next clock. Judge on the current pointers and the flag is a cycle late, and in that cycle you write once more into a full FIFO.

The bug is nasty because it only appears at the boundaries. A long test that stays half full will never hit it. You have to deliberately write a test that fills it and drains it. Worth remembering when you write the Lab 1 testbench.

empty 를 0 으로 리셋하면 리셋 직후에 읽는 쪽이 "데이터가 있다" 고 믿고 초기화 안 된 메모리를 읽어간다. 그 값은 03 절에서 본 X 이고, 시뮬레이션에서는 x 로 보이지만 실물에서는 그냥 아무 값이나 나온다. 그래서 시뮬레이션에서 못 잡고 넘어가면 실리콘에서야 드러난다.

Only empty resets to 1; the other three reset to 0. It looks obvious, and getting it wrong fails badly.

Reset empty to 0 and, right after reset, the reader believes there is data and reads uninitialised memory. That value is the X from §03: visible as x in simulation, but in silicon it is simply whatever was there. Miss it in simulation and it surfaces in the chip.

Lecture 4's rule was "always reset your flip-flops." This goes one step further: "reset them to the right value." All four are reset here, and one wrong value is enough to ruin it.

소유가 이렇게 갈리는 이유는 플래그를 봐야 하는 쪽이 정해져 있기 때문이다. full 은 쓰는 쪽이 보고, 쓰는 쪽은 write clock 으로 돈다. 그러니 full 도 write clock 으로 만들어야 쓰는 쪽이 CDC 없이 바로 읽을 수 있다. empty 는 반대다.

그런데 판정식은 두 포인터를 다 필요로 한다. 여기서 모순이 생긴다.

empty 는 read 도메인 소유인데, 계산하려면 write 도메인의 WP 가 필요하다. full 은 write 도메인 소유인데 read 도메인의 RP 가 필요하다. 즉 어느 쪽으로 정하든 포인터 하나는 반드시 경계를 건넌다.

09 절 도해에서 유일하게 위험할 것 없어 보이던 비교기가 바로 여기서 문제가 된다. 클럭이 하나일 때는 그냥 두 값을 읽으면 됐는데, 이제는 그 읽는 행위가 CDC 다.

But the conditions need both pointers, and that is the contradiction.

empty belongs to the read domain yet needs WP from the write domain; full belongs to the write domain yet needs RP from the read domain. Whichever way you assign ownership, one pointer must cross.

The comparator that looked like the one harmless thing in the §09 figure is exactly what breaks. With one clock you simply read both values; now that reading is a CDC.

4 강의 RDC 도 여기 있다. 4 강 11 절이 reset 이 두 개면 RDC 가 생긴다고 했다. 이 FIFO 는 정확히 그 조건을 만족한다. Write Reset 과 Read Reset 이 서로 다른 register 그룹을 통제하고, 데이터는 그 사이를 흐른다.

이 강의는 RDC 를 다루지 않는다. CDC 만 푼다. 그러니 "왜 reset 쪽은 아무 말이 없지" 싶으면, 그건 이 강의가 생략한 것이지 문제가 없는 게 아니다. 실제 SoC 의 비동기 FIFO 에는 reset 쪽 처리도 들어간다.

Lecture 4's RDC is here too. Lecture 4 §11 said two resets create an RDC, and this FIFO meets that condition exactly: Write Reset and Read Reset control different register groups with data flowing between them.

This lecture does not address RDC, only CDC. So if you wonder why nothing is said about the resets, that is an omission in the lecture rather than an absence of the problem. A real SoC's asynchronous FIFO handles the reset side as well.

2 단 flip-flop 은 metastability 를 없애지 않는다. 첫 단은 여전히 흔들린다. 두 번째 단이 하는 일은 흔들림이 가라앉을 시간을 한 클럭 벌어주는 것뿐이다.

그래서 이건 확률을 낮추는 장치이지 보장이 아니다. 그리고 클럭이 빨라질수록 벌어주는 시간이 줄어든다. 고속 설계에서 3 단, 4 단을 쓰는 이유가 이것이다. 이 강의는 2 단만 다룬다.

더 중요한 것: 2 단 flip-flop 은 한 비트짜리 장치다. 여러 비트에 붙이면 비트마다 독립적으로 동작하므로 비트끼리 어긋나는 것은 전혀 안 막아준다. 그게 다음에 나오는 두 번째 문제다.

A two-flop synchroniser does not remove metastability. The first flop still wobbles. All the second one does is buy one clock period for that wobble to settle.

So it lowers a probability rather than guaranteeing anything, and the faster the clock, the less time it buys. That is why high-speed designs use three or four stages. This lecture covers two.

More importantly: a two-flop synchroniser is a one-bit device. Put it on many bits and each bit works independently, so it does nothing about bits disagreeing with each other. Which is the second problem.

문제 2: 비트마다 도착 시각이 달라서 생기는 잘못된 샘플링. 슬라이드 38쪽 오른쪽 파형이 이걸 그린다. WP[0], WP[1], WP[2] 가 거의 동시에 바뀌는데 완전히 동시는 아니다. 배선 길이와 skew 가 비트마다 다르기 때문이다. 하필 rd_clock 의 엣지가 그 틈에 오면 일부는 새 값, 일부는 옛 값으로 읽힌다.

Problem 2: wrong sampling because bits arrive at different times. The waveform on the right of slide 38 draws it: WP[0], WP[1] and WP[2] change almost but not exactly together, because wire length and skew differ per bit. If the rd_clock edge lands in that gap, some bits read new and some read old.

그 결과 원본에 존재한 적이 없는 포인터 값이 읽힌다. 4 강이 data coherency 라고 부른 것이다. 포인터가 그런 값이 되면 비었는데 안 비었다고 하거나 가득 찼는데 안 찼다고 한다. 후자가 특히 위험하다.

The result is a pointer value that never existed at the source, which Lecture 4 called data coherency. A pointer like that makes the FIFO claim it is not empty when it is, or not full when it is. The second case is the dangerous one.

표에서 binary 열을 보면 3 에서 4 로 갈 때 세 비트가 한꺼번에 바뀐다. gray 열에서는 같은 자리가 010 에서 110 으로 한 비트만 바뀐다.

In the binary column, going from 3 to 4 changes all three bits at once. In the gray column the same step goes 010 to 110: one bit.

그러면 어긋나서 읽혀도 최악이 이전 값 아니면 다음 값이다. 없던 값이 안 나온다. 그리고 이게 안전한 쪽으로만 틀린다. 포인터가 한 칸 옛날 값으로 보이면 실제보다 덜 찬 것으로, 또는 덜 비워진 것으로 보이기 때문이다.

So even a torn sample reads either the old value or the new one, never an invented one. And it errs only on the safe side: a pointer that looks one step stale makes the FIFO appear less full, or less drained, than it really is.

슬라이드에 없는 것: 변환 공식. 슬라이드는 표만 주고 Binary to Gray converter 라는 블록 이름만 보여준다. 실제 공식은 한 줄이다.

gray = binary ^ (binary >> 1)

거꾸로 돌리는 것은 한 줄로 안 되고 위 비트부터 누적 XOR 를 해야 한다. bin[N-1] = gray[N-1] 이고 그 아래는 bin[i] = bin[i+1] ^ gray[i] 다. 이 두 줄은 이 강의 밖에서 가져온 것이고, Lab 1 에서 실제로 필요할 것이라 적어둔다.

Not in the slides: the conversion itself. The slide gives the table and a block labelled Binary to Gray converter, nothing more. The forward direction is one line.

gray = binary ^ (binary >> 1)

The reverse is not one line; it needs a running XOR from the top bit down: bin[N-1] = gray[N-1], then bin[i] = bin[i+1] ^ gray[i]. Both lines come from outside this lecture, noted here because Lab 1 will actually need them.

gray code 의 "한 비트" 성질은 마지막에서 처음으로 돌아올 때도 유지된다. 표의 100 에서 000 으로 가는 것이 그것이고, 한 비트만 바뀐다. 단, 이건 값의 개수가 2 의 거듭제곱일 때만 성립한다.

그래서 비동기 FIFO 의 깊이는 2 의 거듭제곱이어야 한다. 깊이 100 짜리 비동기 FIFO 를 순진하게 만들면 wrap 하는 순간 여러 비트가 동시에 바뀌어서 gray code 를 쓴 의미가 사라진다.

이 제약은 슬라이드에 없다. 슬라이드는 표만 보여주고 넘어간다. 그런데 04 절 현장 감각에서 깊이를 32 로 반올림했던 것이 사실 이 이유였다. 동기 FIFO 에는 없는 제약이라 더 놓치기 쉽다.

The one-bit property holds across the wrap as well, from 100 back to 000 in the table. But only when the number of values is a power of two.

Which means an asynchronous FIFO's depth has to be a power of two. Build a naive depth-100 asynchronous FIFO and several bits change at the wrap, and the gray code has bought you nothing.

This constraint is not in the slides, which show the table and move on. It is, however, the real reason the depth was rounded to 32 back in the §04 exercise. The synchronous FIFO has no such constraint, which makes it easier to forget.

그래서 대가가 무엇인가. 2 단 flip-flop 은 최소 두 클럭을 먹는다. 그래서 받는 쪽이 보는 상대 포인터는 항상 조금 옛날 값이다. 21 쪽 비교표가 "slightly higher due to synchronizer delays" 라고 적은 것이 이것이다.

And the price. A two-flop synchroniser costs at least two clocks, so the pointer each side sees from the other is always slightly stale. That is what the slide 21 table means by "slightly higher due to synchronizer delays."

늦은 게 왜 괜찮은지를 한 번 더 짚고 가자. 늦은 정보는 항상 보수적인 쪽으로만 틀린다.

Worth stating once more why stale is acceptable: stale information only ever errs conservatively.

둘 다 성능을 조금 잃고 정확성을 지킨다. CDC 설계가 대개 이 모양이고, 반대 방향으로 틀리는 설계는 그냥 틀린 설계다.

Both give up a little throughput to keep correctness. Most CDC design has this shape, and a design that errs in the other direction is simply wrong.

Drive it yourself

깊이 4 짜리 FIFO 다. write 를 네 번 누르면 full 이 서고, 이어서 read 를 네 번 누르면 empty 가 선다. 그 두 순간에 포인터의 아래 2 비트가 똑같다는 것을 직접 확인하는 것이 목적이다.

A depth-four FIFO. Press write four times and full goes high; press read four times and empty goes high. The point is to see for yourself that the lower two pointer bits are identical at both of those moments.

Where your hands will slip in Lab 1. None of the four is a syntax error, so all four compile.

1. Sizing the pointer to ADDR_WIDTH, which makes full and empty permanently indistinguishable.
2. Judging the flags on ptr, which is a cycle late at the boundaries.
3. Resetting empty to 0, which reads garbage right after reset.
4. Not blocking writes on full, which loses data and corrupts the state at once.

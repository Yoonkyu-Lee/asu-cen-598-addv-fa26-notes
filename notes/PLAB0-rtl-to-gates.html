00

먼저 P03 · P04 를

The P03 and P04 pages first

이 페이지는 3 강 전 페이지의 3 · 4 단원(flip-flop, comb · ff · latch)과 4 강 전 페이지의 04 단원(sync · async reset)을 안다고 전제한다.

This page assumes units 3 and 4 of the P03 page (the flip-flop; comb, ff and latch) and unit 04 of the P04 page (sync and async reset).

앞의 두 페이지는 "이 회로가 어떻게 도나"를 물었다. 이 페이지는 방향을 뒤집어서 "이 코드는 무슨 회로가 되나"를 묻는다. 합성기가 하는 일이 바로 그것이고, Lab 0 의 리포트 질문 5 번이 그걸 손으로 해보라고 시킨다.

The two pages before asked "how does this circuit run?". This page turns the arrow round and asks "what circuit does this code become?". That is exactly what a synthesis tool does, and Lab 0's report question 5 asks you to do it by hand.

숫자를 줄였다. 랩의 곱셈기는 19 x 18 이고 레지스터는 8 비트다. 이 페이지의 시뮬레이션은 3 x 2 와 3 비트로 줄여서 파형에 찍히는 숫자를 눈으로 읽을 수 있게 했다. 세는 절차는 폭과 무관하게 같다. 05 단원에서 원래 숫자로 돌아간다.

01

물어볼 것은 셋뿐이다

There are only three questions

합성기는 코드를 실행하지 않는다. assign c = en ? a*b : a; 를 "en 이 1 이면 곱하고 아니면 a 를 넣는다" 로 읽으면 소프트웨어를 읽은 것이다. 합성기가 읽는 것은 이거다.

A synthesis tool does not run your code. Reading assign c = en ? a*b : a; as "if en is 1 then multiply, otherwise take a" is reading software. Here is what the tool reads instead.

c 라는 전선 뭉치에 값을 꽂아주는 회로를 만들어라. 그 값은 언제나 a*b 아니면 a 여야 한다.

Build a circuit that keeps a value on the bundle of wires called c. That value must at all times be either a*b or a.

그러려면 a*b 를 만드는 물건도, a 를 그대로 가진 전선도, 둘 중 하나를 고르는 물건도 동시에 존재해야 한다. 셋 다 칩 위에 있다. 여기서부터는 세기만 하면 된다.

For that, the thing that makes a*b, the wire that carries a, and the thing that picks between them must all exist at the same time. All three are on the chip. From here on it is just counting.

02

연산자는 골라 쓰는 게 아니라 항상 거기 있다

An operator is not opted into; it is always there

흔한 그림. "en 이 0 이면 곱셈은 안 일어난다."

The usual picture. "When en is 0, the multiplication does not happen."

고수준 언어에는 short-circuit 이 있다. 조건이 거짓이면 그쪽 식은 아예 계산하지 않는다. 하드웨어에는 그게 없다. 곱셈기는 칩 위에 박힌 물건이고, 입력이 들어오면 출력이 나온다. en 은 곱셈기의 입력이 아니라 그 결과를 쓸지 말지 고르는 MUX 의 select 다.

High level languages short-circuit: if the condition is false, that expression is never evaluated. Hardware has no such thing. The multiplier is a physical object on the chip, and when inputs arrive an output comes out. en is not an input to the multiplier; it is the select on the MUX that decides whether the result gets used.

한 줄 정리. 삼항 연산자는 분기가 아니라 MUX 다. 양쪽 가지가 둘 다 만들어지고, 둘 다 항상 돌고, 둘 중 하나만 밖으로 나간다. 면적과 전력은 쓰는 쪽이 아니라 적은 쪽을 따라간다.

In one line. A ternary operator is not a branch, it is a MUX. Both arms get built, both run all the time, and only one leaves. Area and power follow what you wrote, not what you use.

03

폭이 곧 개수다

The width is the count

앞 단원까지는 신호 하나를 1 비트로 봤다. 실제 설계는 거의 다 버스다. 비트폭은 회로의 모양을 바꾸지 않는다. 개수만 바꾼다.

Up to here a signal has been one bit. Real designs are almost all buses. Width does not change the shape of the circuit. It changes the count.

그림 읽기Reading the picture
  • DFF 는 D flip-flop 이다. D 는 data, 곧 저장할 값이 들어오는 입력 핀 이름이다. 한 개가 1 비트를 기억한다
  • 왼쪽 logic q; 는 폭을 안 적었으므로 1 비트다. 그래서 DFF 하나
  • 오른쪽 logic [7:0] q; 의 [7:0] 은 "7 번 비트부터 0 번 비트까지" 라는 뜻이다. 개수는 7 − 0 + 1 = 8. 그래서 DFF 여덟 개이고, 옆의 [7] 부터 [0] 이 각 DFF 가 맡은 비트 번호다. 맨 위 [7] 이 가장 큰 자리(MSB), 맨 아래 [0] 이 가장 작은 자리(LSB)다
  • 가운데 화살표의 "폭만 바꿨다": 코드에서 바뀐 것은 [7:0] 뿐이고, 회로의 모양(DFF 하나짜리)은 같은데 개수만 8 배가 됐다
  • DFF is a D flip-flop. D stands for data, the name of the input pin the value to be stored comes in on. One of them remembers one bit
  • Left, logic q; has no width written, so it's one bit: one DFF
  • Right, logic [7:0] q;: [7:0] reads "bit 7 down to bit 0". That's 7 − 0 + 1 = 8 bits, so eight DFFs, and the [7] to [0] beside them are the bit each DFF holds. [7] at the top is the most significant bit (MSB), [0] at the bottom the least significant (LSB)
  • "Only the width changed" on the middle arrow: the only edit in the code is [7:0]; the shape (a single DFF) stays the same and the count goes up eightfold

그래서 합성 리포트의 숫자를 손으로 어림할 수 있다. Lab 0 의 area.rep 는 순차 셀이 421 개라고 적는다. 설계 안의 모든 reg 선언의 비트 수를 더하면 그 근처가 나온다.

This lets you estimate a synthesis report by hand. Lab 0's area.rep says there are 421 sequential cells, and adding up the bit widths of every reg in the design lands near that.

근처이지 같지는 않다. 세어서 나온 수는 위쪽 한계다. 합성기는 아무도 안 읽는 레지스터를 통째로 쳐낸다. Lab 0 의 muxsel_flopped 가 정확히 그렇다. reg [7:0] 로 선언되고 값도 받지만 설계 어디에서도 읽지 않는다. 그래서 cell.rep 에 한 개도 없다. RTL 은 8 개를 적었고 실물은 0 개다.

Near, not equal. What you counted is an upper bound. The tool deletes any register nobody reads, and Lab 0's muxsel_flopped is exactly that: declared reg [7:0] and assigned, but read nowhere in the design. So cell.rep holds none of them. The RTL wrote eight; the silicon has zero.

폭이 다르면 MUX 가 폭을 맞춘다. en ? a*b : a 에서 a*b 는 37 비트이고 a 는 19 비트다. MUX 는 37 비트짜리 하나이고, a 쪽 입력의 남는 위쪽 18 비트는 채워서 올라간다. a 가 unsigned 면 0 으로, signed 면 부호 비트로 채운다. 도해에 안 그려도 되지만 알고는 있어야 한다.

When the widths differ, the MUX sets the width. In en ? a*b : a the product is 37 bits and a is 19. The MUX is a single 37 bit one, and the spare 18 bits above the a input get filled in: with zeros if a is unsigned, with the sign bit if it is signed. You need not draw it, but you should know it is there.

리셋을 어디에 적었느냐가 그림을 바꾼다

Where you wrote the reset changes the drawing

4 강 전 페이지 04 단원이 sync 와 async reset 의 동작 차이를 다뤘다. 여기서 볼 것은 그림이다. 같은 레지스터인데 리셋을 어디에 적었느냐로 상자 개수가 달라진다.

Unit 04 of the P04 page covered how sync and async reset behave differently. What to look at here is the drawing. Same register, and where you wrote the reset changes how many boxes come out.

두 카드를 나란히 두었다. 같은 프레임 번호로 맞춰 놓고 비교하라. 회로 칸을 먼저 보고, 그 다음에 파형을 보라.

In one line. In the sensitivity list, it goes to the flop's dedicated pin; inside the block only, it goes into the logic in front of D. Lines 152 to 158 of Lab 0 are inside the block, so they are synchronous. Draw a reset pin and the drawing is wrong.

질문Question답Answer

2. 조건이 몇 갈래2. How many branches둘. 2:1 MUX 하나, select 는 en. 그리고 a*b 를 만들어줄 곱셈기 하나Two. One 2:1 MUX with en as select, plus one multiplier to produce a*b
3. 폭이 몇3. What widtha 19 비트, b 18 비트 → 곱은 37 비트. MUX 도 37 비트a is 19 bits, b is 18, so the product is 37. The MUX is 37 bits too
그림 읽기Reading the picture
  • b [17:0], a [18:0]: 대괄호는 비트 범위다. [17:0] 은 17 − 0 + 1 = 18 비트, [18:0] 은 19 비트
  • MULT 는 곱셈기(multiplier)다. 안의 19 x 18 은 19 비트 수와 18 비트 수를 곱한다는 뜻이다
  • a*b [36:0]: 곱의 폭은 두 입력 폭의 합이다. 19 + 18 = 37 비트, 그래서 [36:0]
  • a 선 위의 점: 점은 선이 갈라진다는 표시다. a 는 곱셈기로도 가고, 아래로 꺾여 MUX 로도 간다. 같은 신호가 두 곳에 동시에 닿는다
  • MUX 의 1 과 0: 데이터 값이 아니라 select 값이다. en 이 1 이면 위쪽 입력(a*b), 0 이면 아래쪽 입력(a)이 나간다. 코드의 en ? a*b : a 순서와 같다
  • c [36:0]: MUX 출력은 넓은 쪽에 맞춰 37 비트다. 19 비트인 a 는 위쪽 18 비트를 채워서 들어간다 (03 단원 함정)

눈여겨볼 곳은 en 선이 MUX 에만 닿고 곱셈기에는 닿지 않는다는 것이다. en 이 0 이어도 곱셈기는 a 와 b 를 받아 계속 곱하고 있다.

  • b [17:0], a [18:0]: the brackets are a bit range. [17:0] is 17 − 0 + 1 = 18 bits, [18:0] is 19 bits
  • MULT is the multiplier. 19 x 18 inside it means a 19-bit number times an 18-bit one
  • a*b [36:0]: a product is as wide as its two inputs added: 19 + 18 = 37 bits, hence [36:0]
  • The dot on the a wire: a dot marks a split. a goes into the multiplier and also turns down to the MUX; the same signal reaches both at once
  • The 1 and 0 on the MUX aren't data values; they're select values. With en = 1 the top input (a*b) goes out, with en = 0 the bottom one (a). Same order as en ? a*b : a in the code
  • c [36:0]: the MUX output takes the wider width, 37 bits. The 19-bit a has its top 18 bits filled in on the way (the trap in unit 03)

The thing to notice: the en wire touches only the MUX, never the multiplier. Even with en at 0, the multiplier keeps taking a and b and multiplying.

  • 8'd0: Verilog 의 숫자 표기다. 8 은 폭 8 비트, 'd 는 10 진수, 0 은 값. 곧 00000000. 코드의 muxsel_flopped <= 8'd0; 쪽이다

  • 8 x DFF: DFF 여덟 개를 한 상자로 줄여 그린 것이다. 아래 그림이 펼친 모양이다
  • DFFPOSX1: 이 과목 Lab 이 쓰는 표준 셀 라이브러리의 셀 이름이다. DFF (D flip-flop) + POS (positive edge, 클럭이 올라갈 때 잡는다) + X1 (구동 세기 1 배, 가장 작은 크기). 리셋 핀이 없는 그냥 flip-flop 이다
  • 갈색 선과 삼각형: clk 이고, 삼각형이 flip-flop 의 클럭 핀이다
  • 주황 화살표: 리셋(clr)이 flip-flop 에 직접 닿지 않고 D 앞의 MUX 를 지난다는 표시다. 그래서 리셋도 클럭 엣지가 와야 반영된다. 이게 동기 리셋이다

이 그림은 RTL 이 적은 그대로다. 03 단원 함정에서 본 대로 실제 Lab 0 합성에서는 muxsel_flopped 를 아무도 안 읽어서 이 여덟 개가 통째로 지워진다.

  • muxsel [7:0]: the 8-bit value to be stored, the muxsel_flopped <= muxsel; side of the code
  • 8'd0: Verilog number syntax. 8 is the width in bits, 'd means decimal, 0 is the value: 00000000. The muxsel_flopped <= 8'd0; side
  • The 0 and 1 on the MUX are select values, as before. With clr = 0 the top input, muxsel, goes out; with clr = 1 the bottom one, 8'd0. Don't mix that 0 up with the 0 in 8'd0, which is data
  • 8 x DFF: eight DFFs drawn as one box. The next picture shows them spread out
  • DFFPOSX1: the cell name in the standard cell library the course labs use. DFF (D flip-flop) + POS (positive edge: it captures as the clock rises) + X1 (drive strength 1, the smallest size). A plain flip-flop with no reset pin
  • Brown line and triangle: that's clk, and the triangle is the flip-flop's clock pin
  • Amber arrow: the reset (clr) doesn't reach the flip-flop directly; it goes through the MUX in front of D. So even the reset waits for a clock edge. That's a synchronous reset

This is what the RTL says. As the trap in unit 03 showed, the real Lab 0 synthesis deletes all eight, because nobody reads muxsel_flopped.

위 그림의 8 x DFF 는 줄여 쓴 것이다. flip-flop 하나는 1 비트만 저장하므로 8 비트를 담으려면 여덟 개가 필요하다. 같은 상자가 여덟 번 반복될 뿐이라 도면에서는 보통 하나로 줄여 그린다. 펼치면 이렇게 생겼다.

The 8 x DFF above is shorthand. One flip-flop stores one bit, so eight bits need eight of them. It is the same box repeated eight times, which is why drawings usually collapse it into one. Expanded, it looks like this.

그림 읽기Reading the picture

한 줄(한 비트)만 따라가 보자. 맨 위 줄이 7 번 비트다.

  1. muxsel[7] 이 그 줄 MUX 의 위쪽 입력으로 들어간다
  2. MUX 의 아래쪽 입력 옆 회색 0 은 데이터 값 0 이다. 앞 그림의 8'd0 을 비트 하나씩 나눠 준 것이다. 앞 그림 MUX 의 select 값 0 과는 다른 것이다
  3. 왼쪽 세로선 clr 에서 점을 찍고 나온 선이 MUX 로 들어간다. 이것이 select 다. 앞 그림과 같이 clr 이 0 이면 muxsel[7], 1 이면 0 이 나간다
  4. MUX 출력이 DFF 의 D 로 들어가고, Q 에서 muxsel_flopped[7] 이 나온다
  5. 세로선 clk 에서 나온 갈색 선이 DFF 아래 삼각형(클럭 핀)으로 들어간다

나머지 일곱 줄은 비트 번호만 다르고 똑같다. 세로선 두 개 clk 과 clr 은 위에서 아래까지 이어져 여덟 줄이 공유한다. 점이 찍힌 곳만 연결된 자리이고, 선이 그냥 겹쳐 지나가는 곳은 연결이 아니다 (그림 맨 아래 문장).

Follow one row, one bit. The top row is bit 7.

  1. muxsel[7] goes into the top input of that row's MUX
  2. The grey 0 beside the bottom input is the data value 0: one bit of the previous picture's 8'd0. It isn't the select value 0 from the previous picture's MUX
  3. A line leaves the vertical clr wire at a dot and enters the MUX: that's the select. As before, clr = 0 passes muxsel[7], clr = 1 passes 0
  4. The MUX output enters the DFF's D, and muxsel_flopped[7] comes out of Q
  5. A brown line from the vertical clk wire runs into the triangle under the DFF, its clock pin

The other seven rows are identical apart from the bit number. The two vertical wires, clk and clr, run top to bottom and all eight rows share them. Only a dot marks a connection; where lines merely cross, they aren't connected (the sentence at the bottom of the picture).

한 줄 정리. "8 비트 flip-flop" 이라는 부품은 없다. 1 비트짜리 여덟 개를 나란히 놓고 clk 과 clr 을 같이 물린 것이고, 그 묶음을 register 라고 부른다. reg [15:0] 이었으면 이 그림의 숫자만 16 으로 바뀐다.

In one line. There is no such part as an "8 bit flip-flop". It is eight one bit flip-flops side by side with clk and clr tied together, and that bundle is called a register. Had it been reg [15:0], only the number in this drawing would change.

06

내 그림이 맞는지 툴에게 물어본다

Ask the tool whether your drawing is right

여기가 이 페이지에서 제일 쓸모 있는 부분이다. 그림을 추측으로 끝내지 않아도 된다. 합성기가 이미 답을 갖고 있고, 리포트에 적어 놨다.

This is the most useful part of the page. You do not have to leave the drawing as a guess. The synthesis tool already has the answer and wrote it down.

// ~/labs/lab0/work/synth
grep -c DFFPOSX1 cell.rep            // 421. 순차 셀 수와 같다// 421, the same as the sequential cell count
grep -ci muxsel_flopped cell.rep     // 0. 쳐냈다// 0, they were swept
grep -ic "dffs\|dffr\|dffneg" cell.rep  // 0. 비동기도 negedge 도 없다// 0, no async and no negedge

두 번째 줄이 03 단원의 함정을 눈으로 확인시킨다. RTL 이 적은 flip-flop 8 개가 netlist 에 하나도 없다. 세 번째 줄은 "이 설계의 리셋은 전부 동기" 를 설계 전체 수준에서 증명한다. 첫 줄의 421 이 area.rep 의 순차 셀 수와 같으니 순차 셀이 이 한 종류뿐이라는 것도 같이 나온다.

The second line makes unit 03's trap visible: not one of the eight flip-flops the RTL wrote is in the netlist. The third proves, across the whole design, that every reset here is synchronous. And because the 421 on the first line equals the sequential cell count in area.rep, that one cell type is all there is.

timing.rep 은 critical path 의 양 끝 셀 이름을 그대로 적는다.

timing.rep names the cells at both ends of the critical path, verbatim.

Startpoint: negate_flopped_3_reg
            (rising edge-triggered flip-flop clocked by clk)
negate_flopped_3_reg/CLK (DFFPOSX1)

DFFPOSX1 은 D Flip-Flop, POSitive edge, drive strength 1 이다. 도해에 "positive edge DFF" 라고 쓴 것이 지어낸 말이 아니라 툴이 실제로 고른 셀 이름이라는 뜻이다.

DFFPOSX1 reads as D Flip-Flop, POSitive edge, drive strength 1. So "positive edge DFF" on the drawing is not something you made up; it is the name of the cell the tool actually picked.

한 줄 정리. 마지막 grep 이 핵심이다. 비동기 리셋 셀이 안 나와야 "이 레지스터는 동기 리셋" 이라는 내 주장이 증명된다. 도해 옆에 이 한 줄을 붙이면 그림이 주장에서 증거로 바뀐다.

In one line. The last grep is the one that matters. No async reset cell may appear if the claim "this register has a synchronous reset" is to hold. Put that one line next to the drawing and it turns from an assertion into evidence.

결론부터

The short version

이 강의는 같은 것을 더 잘 만드는 법의 목록이다. 기능은 맞다고 치고 작게, 빠르게, 적게 먹게 만든다. 슬라이드 20 쪽에 기법이 스물 몇 개 들어가므로 대부분 이름과 한 줄로 지나간다.

This lecture is a list of ways to build the same thing better. Function is assumed correct; make it smaller, faster, hungrier for less. Twenty-odd techniques in twenty slides means most get a name and one line.

코드가 아니라 회로

The circuit, not the code

슬라이드 6쪽은 한 문장뿐이다. Understand what hardware you are designing. Not what you are coding.

Slide 6 is a single sentence. Understand what hardware you are designing. Not what you are coding.

앞 슬라이드의 제목이 Design Guidelines vs. Design Efficiency 다. vs. 가 핵심이다. 모듈화, 추상화, naming convention 은 전부 사람을 위한 것이지 회로를 위한 게 아니다. 모듈 경계가 깔끔하면 읽기는 좋은데 synthesis 가 그 경계를 넘나들며 최적화하지 못한다.

The slide before it is titled Design Guidelines vs. Design Efficiency. The vs. is the point. Modularity, abstraction and naming conventions are for people, not for the circuit. Clean module boundaries read well and stop synthesis from optimising across them.

가장 선명한 예가 operand isolation 이다. 슬라이드 본문에는 정의 한 줄뿐인데 발표자 노트에 코드가 들어 있다. 이 덱에서 노트가 붙은 유일한 장이다.

The sharpest example is operand isolation. The slide body has one line of definition and the speaker notes carry the code. The only slide in the deck with notes.

// 전. enable 이 0 이어도 a 나 b 가 바뀌면 곱셈기가 통째로 토글한다
wire [31:0] mult_out = a * b;
always @(posedge clk) if (enable) result <= mult_out;

// 후. 입력을 먼저 0 으로 묶으면 안쪽이 안 움직인다
wire [31:0] a_iso = enable ? a : 32'b0;
wire [31:0] b_iso = enable ? b : 32'b0;
wire [63:0] mult_out = a_iso * b_iso;
// before. with enable low, a change on a or b still toggles the whole multiplier
wire [31:0] mult_out = a * b;
always @(posedge clk) if (enable) result <= mult_out;

// after. pin the inputs to zero first and nothing inside moves
wire [31:0] a_iso = enable ? a : 32'b0;
wire [31:0] b_iso = enable ? b : 32'b0;
wire [63:0] mult_out = a_iso * b_iso;

위 코드는 기능적으로 완전히 맞다. enable 이 0 이면 결과를 안 쓰니 틀릴 일이 없고, 시뮬레이션에서 두 코드가 똑같이 동작한다. 검증도 똑같이 통과한다. 차이는 합성된 회로에서만 보이고 전력 리포트에서만 드러난다. 슬라이드 6쪽의 문장이 뜻하는 바가 이것이다.

The first version is functionally perfect. With enable low the result is discarded, and both versions behave identically in simulation. Verification passes either way. The difference exists only in the synthesised circuit and only shows up in a power report. That is what slide 6 means.

대가도 있다. mux 두 개가 곱셈기 입력 경로에 붙으므로 critical path 가 조금 길어진다. 곱셈기가 충분히 크고 enable 이 자주 0 일 때만 이득이다.

It costs something too. The two muxes sit on the multiplier input path, so the critical path grows a little. It only pays when the multiplier is big and enable is often low.

PPA 와 맞바꿈

PPA and the trade

Performance 자리에 Delay 를 쓰면 방향이 반대가 된다. 슬라이드 19쪽의 연습 표가 Delay 열을 쓴다. delay 는 작을수록 좋고 performance 는 클수록 좋다. 이걸 놓치면 표를 통째로 거꾸로 채운다.

Putting Delay where Performance was flips the direction. The exercise table on slide 19 uses a Delay column. Smaller delay is better, larger performance is better. Miss it and you fill the whole table backwards.

예외도 있다. bitwidth 축소(FP32 → INT8)와 operator strength reduction(곱셈 → shift)은 셋 다 좋아진다. 공짜처럼 보이는데 내주는 것이 표 바깥에 있을 뿐이다. 앞엣것은 정확도, 뒤엣것은 일반성이다.

There are exceptions. Bitwidth reduction (FP32 → INT8) and operator strength reduction (multiply to shift) improve all three. They look free because what they cost is outside the table: accuracy for the first, generality for the second.

Clock gating 과 power gating 은 다르다. 구별 기준 한 줄은 상태가 남는가다.

Clock gating and power gating differ. The one line test is whether state survives.

  • Clock gating · clock 만 끊는다. flip-flop 이 값을 그대로 들고 있다. 다시 켜는 비용이 거의 없어 짧게 쉴 때
  • Clock gating · cut the clock only. Flip-flops keep their values. Waking is nearly free, so it is for short idles
  • Power gating · 전원을 내린다. 상태가 날아간다. 복원 비용이 커서 길게 쉴 때
  • Power gating · cut the supply. State is lost. Restoring costs enough that it is for long idles

Concurrency 와 pipelining 도 다르다. 숨김 슬라이드 13쪽이 이 구별을 위해 있다. 슬라이드의 문장이 가장 깔끔하다. Concurrency does things side-by-side; pipelining instead uses stages (like a factory line). concurrency 는 유닛을 여러 개 두고, pipelining 은 유닛 하나씩을 register 로 이어 붙인다. 둘을 같이 쓸 수도 있다.

Concurrency and pipelining differ too. Hidden slide 13 exists for this, and its own sentence is the cleanest: Concurrency does things side-by-side; pipelining instead uses stages (like a factory line). Concurrency duplicates units, pipelining chains one of each through registers. You can do both.

도구와 사람의 경계

Tool versus human

슬라이드 15쪽도 한 문장이다. Synthesis and Physical Design tools can do many of these. RTL designers need to focus on what they can't.

Slide 15 is another single sentence. Synthesis and Physical Design tools can do many of these. RTL designers need to focus on what they can't.

슬라이드는 어느 것이 어느 쪽인지 말해주지 않는다. 아래는 자세한 판이 각 기법의 정의에서 갈라본 것이고, 가르는 기준은 하나다. 도구는 의미를 안 바꾸는 변환만 한다.

The slide does not sort them for you. The split below is the full note reasoning from the definitions, on one rule: a tool only applies transformations that preserve meaning.

대체로 도구Mostly the tool 대체로 사람Mostly you
logic minimization, 상수 전파, strength reduction, tree balancing, retiminglogic minimisation, constant propagation, strength reduction, tree balancing, retiming pipeline 단수, precision, LUT 로 바꿀지, 구간 선형 근사, building block 아키텍처, 무엇을 상수로 고정할지pipeline depth, precision, whether to go to a LUT, piecewise linear, block architecture, which parameters to freeze

가운데도 있다. clock gating 과 resource sharing 은 도구가 상당 부분 해주는데 RTL 모양이 도구의 손을 묶는다. 슬라이드 8쪽이 곱셈을 state machine 바깥에 두라고 한 것이 그 이야기다.

Some sit in between. Clock gating and resource sharing are largely automatic, and the shape of the RTL can tie the tool's hands. That is what slide 8 means by keeping the multiply outside the state machine.

PPA 밖의 축

Axes outside PPA

슬라이드 16쪽과 17쪽이 축 둘을 더 든다. 여기서 최적화한다는 것은 대개 더 넣는다는 뜻이라 방향이 반대다.

Slides 16 and 17 add two more axes, where optimising usually means adding, so the direction is reversed.

  • Security · secure boot 과 암호화 (RSA, ECC, SHA, AES 블록), 하드웨어 난독화, side-channel 완화, 접근 제어 (ARM TrustZone)
  • Security · secure boot and encryption (RSA, ECC, SHA, AES blocks), hardware obfuscation, side-channel mitigation, access control (ARM TrustZone)
  • Reliability · parity 와 ECC 로 오류 검출과 정정, TMR 같은 중복 (같은 회로 셋에 다수결, 면적 세 배 이상)
  • Reliability · parity and ECC for detection and correction, redundancy such as TMR (three copies and a vote, more than triple the area)

ECC 가 이 덱 안에서 두 가지 뜻이다. 슬라이드가 연달아 나오므로 문맥으로 갈라야 한다.

ECC means two things in this one deck, on back to back slides, so context is the only separator.

  • 16쪽 (security) · Elliptic Curve Cryptography. RSA, SHA, AES 와 나란히 있다
  • Slide 16, security · elliptic curve cryptography, listed with RSA, SHA and AES
  • 17쪽 (reliability) · Error-Correcting Code. parity bit 와 나란히 있다
  • Slide 17, reliability · error-correcting code, listed with parity bits

Side-channel 완화가 이 강의의 나머지와 정면으로 충돌한다. dummy cycle 과 shuffling 은 일부러 쓸데없는 일을 시키는 것이다. 연산 시간과 전력이 데이터에 따라 달라지면 그 차이로 비밀이 새기 때문이다. 슬라이드 4쪽의 no free lunch 가 이렇게도 성립한다.

Side-channel mitigation runs into the rest of the lecture. Dummy cycles and shuffling mean doing pointless work on purpose, because if time or power varies with the data, that variation leaks the secret. Another shape of the no free lunch rule from slide 4.

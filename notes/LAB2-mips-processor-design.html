파이프라인을 왜 만듬? · 문제: 명령어 하나가 클럭 한 번을 통째로 쓴다

Why pipeline at all? · The problem: one instruction takes a whole clock

Lab 이야기 전에, 주어진 회로가 한 클럭 동안 무슨 일을 하는지부터 본다.

Before the lab itself, a look at what the given circuit does in one clock.

주어진 것: 클럭 한 번에 명령어 하나

What we were given: one instruction per clock

주어진 코드는 교재 장의 single-cycle MIPS 다. 상승 엣지에 PC 가 바뀌면 같은 클럭 주기 안에 다섯 가지 일이 차례로 일어난다. 그 PC 로 instruction memory 를 읽고, 명령어의 rs · rt 로 register file 을 읽고, ALU 가 계산하고, lw 라면 data memory 를 읽고, 결과가 다음 상승 엣지에 register file 에 써진다. 이 다섯 가지가 한 주기 안에 다 끝나야 한다.

The given code is the single-cycle MIPS from the book chapter. When PC changes on a rising edge, five things happen in turn within the same clock period: the instruction memory is read at that PC, the register file is read at the instruction's rs and rt, the ALU computes, a load reads data memory, and the result is written into the register file on the next rising edge. All five have to finish inside one period.

그림 읽기. lw $2, 0($0) 를 따라간다. ① PC 가 가리키는 칸에서 명령어 8c020000 을 읽는다. ② 명령어의 rs 필드($0)로 register file 을 읽는다. ③ ALU 가 $0 + 0, 즉 주소 0 을 만든다. ④ data memory 의 0 번지를 읽는다. ⑤ 그 값이 mux 를 지나 다음 상승 엣지에 $2 에 써진다. 클럭 주기는 ① 부터 ⑤ 까지 전부를 덮어야 한다.

Reading the figure. Follow lw $2, 0($0). ① Read instruction 8c020000 at PC. ② Read the register file at the rs field ($0). ③ The ALU forms $0 + 0, address 0. ④ Read data memory at address 0. ⑤ The value goes through the multiplexer and is written into $2 on the next rising edge. The clock period has to cover all of ① to ⑤.

문제: 제일 긴 명령어가 박자를 정한다

The problem: the longest instruction sets the beat

명령어마다 지나가는 길이 다르다. lw 는 다섯 칸을 다 지난다. add 는 data memory 를 건너뛴다. beq 는 ALU 의 비교(zero)로 다음 PC 를 정하고 끝난다(주어진 코드의 pcsrc = branch & zero). 그런데 클럭은 회로 전체에 하나뿐이라 주기는 가장 긴 lw 에 맞춰야 하고, 짧은 명령어는 남은 시간 동안 할 일이 없다.

Different instructions walk different paths. A load uses all five parts. An add skips data memory. A beq decides the next PC from the ALU's comparison (zero) and is done (pcsrc = branch & zero in the given code). But there's one clock for the whole circuit, so the period has to fit the longest instruction, the load, and shorter instructions have nothing to do for the rest of it.

문제는 이렇게 푼다. 길을 다섯 토막으로 자르고 토막 사이에 레지스터를 둔다(02 절). 그러면 클럭 주기는 가장 긴 토막에만 맞추면 된다. 대신 다섯 칸에 다섯 명령어가 동시에 있게 되고, 그 명령어들이 서로의 결과를 기다리는 문제가 생긴다(03~06 절).

The fix: cut the path into five pieces and put a register between pieces (section 02). Then the period only has to fit the longest piece. The catch is that five instructions now sit in the five pieces at once, and they end up waiting on each other's results (sections 03 to 06).

02

해결 · 다섯 칸으로 자르고 칸 사이에 레지스터를 둔다

Fix · Cut it into five stages with registers in between

과제 2 번. 클럭 주기는 가장 긴 토막 하나에만 맞추면 된다.

Task 2. The clock period only has to fit the longest single piece.

블록 사이에 flip-flop 묶음(pipeline register)을 넣으면 한 클럭에 한 토막만 지나면 된다. 다섯 토막의 이름은 F (fetch), D (decode), E (execute), M (memory), W (writeback), 레지스터 넷은 경계 이름을 따서 IF/ID, ID/EX, EX/MEM, MEM/WB 다.

Put a bank of flip-flops (a pipeline register) between blocks, and each clock only has to cover one piece. The five pieces are F (fetch), D (decode), E (execute), M (memory) and W (writeback); the four registers are named after the boundaries they sit on: IF/ID, ID/EX, EX/MEM, MEM/WB.

그림 읽기. 왼쪽부터. F 는 PC 로 instruction memory 를 읽는다. IF/ID 는 그 명령어(instrD)와 PC+4(pcplus4D)를 붙잡는다. D 는 register file 을 읽고, control 이 명령어를 해독하고, beq 비교(==)와 분기 목적지 계산(target)도 여기서 한다(06 절). ID/EX 는 읽은 두 값(rd1E, rd2E), immediate, 레지스터 번호 셋, 제어 신호를 넘긴다. E 는 ALU 앞에 forwarding mux(fwd)를 둔다(04 절). M 은 data memory, W 는 ALU 결과와 메모리 값 중 하나를 골라 register file 에 다시 쓴다(파란 선). 레지스터마다 valid 비트가 하나씩 붙어 그 칸에 진짜 명령어가 있는지 표시한다(09 절).

Reading the figure. From the left. F reads instruction memory at PC. IF/ID holds that instruction (instrD) and PC+4 (pcplus4D). D reads the register file, control decodes the instruction, and the beq comparison (==) and branch target are computed here too (section 06). ID/EX passes on the two values read (rd1E, rd2E), the immediate, three register numbers and the control signals. E has forwarding multiplexers (fwd) in front of the ALU (section 04). M is data memory, and W picks either the ALU result or the memory value and writes it back into the register file (blue line). Each register carries a valid bit saying whether its slot holds a real instruction (section 09).

명령어 하나는 느려지고, 일은 빨라진다

Each instruction gets slower, the work gets faster

그림 읽기. lw $2, 0($0) 줄을 본다. cycle 2 에 F, 3 에 D, 4 에 E(주소 0 계산, aluoutE = 0), 5 에 M(메모리 읽기), 6 에 W(readdataW = 9 를 $2 에). 명령어 하나가 끝나는 데 다섯 사이클이다. 그런데 W 열을 세로로 보면 cycle 4 의 addi $1, 5 의 sw $1, 6 의 lw $2, 7 의 addi $3, 8 의 addi $4 로 매 사이클 하나씩 끝난다. 처음 네 사이클은 줄이 차는 시간(fill)이다.

Reading the figure. Follow the lw $2, 0($0) row: F in cycle 2, D in 3, E in 4 (address 0, aluoutE = 0), M in 5 (memory read), W in 6 (readdataW = 9 into $2). One instruction takes five cycles. Now read the W column downwards: addi $1 in cycle 4, sw $1 in 5, lw $2 in 6, addi $3 in 7, addi $4 in 8. One finishes every cycle. The first four cycles are the pipeline filling up.

리포트의 성능 표가 이것을 옮긴 것이다. 주기가 짧아지는 만큼 같은 프로그램이 빨리 끝나고, 명령어 하나의 latency 는 오히려 다섯 배가 된다. 면적과 클럭 줄은 11 절에서 본다.

The report's performance table records exactly this. The shorter period makes the same program finish sooner, while one instruction's latency goes up fivefold. The area and clock rows are in section 11.

대가. 다섯 칸에 다섯 명령어가 있으면 서로 방해한다. 뒤 명령어가 앞 명령어의 결과를 아직 못 받거나(03, 05 절), 앞의 분기가 정해지기 전에 뒤 명령어를 이미 가져온다(06 절). 이걸 hazard 라고 부른다.

The price. Five instructions in five stages get in each other's way. A later instruction may need a result an earlier one hasn't delivered yet (sections 03 and 05), or a branch may be undecided while the next instructions are already fetched (section 06). These are called hazards.

문제 1 · 바로 앞 명령어의 결과가 아직 레지스터 파일에 없다

Problem 1 · The result of the instruction just before isn't in the register file yet

여기서 쓰는 사이클 표와 파형은 전부 제출 코드를 다시 돌린 기록에서 그렸다(10 절).

Every cycle chart and waveform here is drawn from a re-run of the submitted code (section 10).

add_forwarding 테스트의 프로그램이다. addi $1, $0, 5, addi $2, $0, 7, add $3, $1, $2, add $4, $3, $2, add $5, $4, $3, sw $5, 0($0). 세 add 가 바로 앞의 결과를 쓴다.

The program in the add_forwarding test: addi $1, $0, 5, addi $2, $0, 7, add $3, $1, $2, add $4, $3, $2, add $5, $4, $3, sw $5, 0($0). Each add uses the result just before it.

그림 읽기. add $4, $3, $2 줄은 cycle 4 에 D 에서 $3 을 읽고 cycle 5 에 E 에서 그 값으로 더한다. 그런데 $3 을 만드는 add $3 은 cycle 4 에 E 에서 계산하고, register file 에 써지는 것은 W 가 끝나는 cycle 6 끝이다. 레지스터에서 읽으면 cycle 4 의 $3, 즉 아직 아무도 안 쓴 옛 값을 쓰게 된다. 값은 cycle 4 에 이미 ALU 에서 나와 있는데, 레지스터에 늦게 들어갈 뿐이다.

Reading the figure. The add $4, $3, $2 row reads $3 in D in cycle 4 and adds with it in E in cycle 5. But add $3, which produces $3, computes it in E in cycle 4, and it lands in the register file only at the end of W, the end of cycle 6. Reading the register gives the old $3, one nobody has written yet. The value already came out of the ALU in cycle 4; it just gets into the register late.

앞 명령어가 쓸 레지스터를 뒤 명령어가 먼저 읽는 것을 read-after-write (RAW) data hazard 라고 한다. 푸는 길은 둘이다. 써질 때까지 뒤 명령어를 멈추거나(stall), 이미 나온 값을 뒤 명령어에게 바로 건네주거나(forwarding). 과제 4 번은 ADD 에 forwarding 을 요구한다.

A later instruction reading a register before an earlier one has written it is a read-after-write (RAW) data hazard. There are two ways out: hold the later instruction until the write happens (a stall), or hand it the value that already exists (forwarding). Task 4 asks for forwarding on ADD.

해결 1 · 결과를 M 과 W 에서 E 로 되돌려 준다

Fix 1 · Hand results back from M and W to E

과제 4 번의 forwarding. 값을 기다리지 않고, 이미 나와 있는 자리에서 가져온다.

Task 4's forwarding: don't wait for the value, take it from where it already is.

값은 이미 회로 안에 있다. E 에서 계산된 값은 다음 사이클 EX/MEM 레지스터(aluoutM)에, 그다음 사이클 MEM/WB 를 지나 resultW 에 있다. 그래서 E 의 입구, ALU 앞에 mux 를 둬서 거기서 가져온다.

The value is already in the circuit. Computed in E, it sits in the EX/MEM register as aluoutM the next cycle, and as resultW after MEM/WB the cycle after. So put a multiplexer at the entrance of E, in front of the ALU, and take it from there.

그림 읽기. 위 mux 는 ALU 의 첫 피연산자 srcaE 를 고른다. 00 이면 D 에서 읽어 ID/EX 로 넘어온 rd1E, 10 이면 EX/MEM 의 aluoutM(한 명령어 앞의 결과), 01 이면 MEM/WB 를 지난 resultW(두 명령어 앞의 결과)다. 아래 mux 도 같은 방식으로 두 번째 피연산자 writedataE 를 고른다. 이 값은 sw 가 메모리에 쓸 데이터이기도 하다.

Reading the figure. The top multiplexer picks the ALU's first operand, srcaE: 00 is rd1E, read in D and carried in ID/EX; 10 is aluoutM from EX/MEM, the result of one instruction ahead; 01 is resultW after MEM/WB, two instructions ahead. The bottom one picks the second operand, writedataE, the same way. That value is also the data a sw stores.

고르는 규칙은 레지스터 번호 비교다. M 에 있는 명령어가 레지스터를 쓰고(regwriteM), 그 번호(writeregM)가 E 명령어의 rs(rsE)와 같으면 10. 아니고 W 가 그렇다면 01. 둘 다 아니면 00.

The rule is a register-number match. If the instruction in M writes a register (regwriteM) and its number (writeregM) equals the rs of the instruction in E (rsE), pick 10. Otherwise, if the one in W does, pick 01. Otherwise 00.

조건 넷이 각자 이유가 있다. M 을 먼저 본다. M 과 W 가 같은 레지스터를 쓰면 M 쪽이 나중 명령어라 더 새 값이다. $0 은 건네지 않는다. $0 은 늘 0 이라 누가 써도 의미가 없다. !memtoregM: M 에 있는 것이 lw 면 aluoutM 은 값이 아니라 주소다. 그 경우는 05 절. validM · validW: bubble 이나 버린 명령어는 건네지 않는다(09 절).

Each of the four conditions is there for a reason. M is checked first: if M and W both write the same register, M holds the later instruction and so the newer value. $0 is never forwarded: it is always 0, so writing it means nothing. !memtoregM: if the instruction in M is a load, aluoutM is an address, not the value; that case is section 05. validM, validW: bubbles and discarded instructions don't forward (section 09).

세 add 가 한 사이클도 멈추지 않고 E 를 지나갔다. 과제는 ADD 에만 요구했지만 회로는 명령어를 가리지 않는다. 규칙이 레지스터 번호만 보기 때문이다. all_instructions 테스트의 cycle 13 에서 sw $7 이 바로 앞 slt $7 의 결과를 같은 길(forwardBE = 2)로 받는다(05 절 슬라이더).

The three adds go through E without a single stall. The task only asked for ADD, but the circuit doesn't care which instruction it is, since the rule only looks at register numbers. In cycle 13 of the all_instructions test, sw $7 gets the result of the slt $7 right before it along the same path (forwardBE = 2; see the slider in section 05).

하나 더: W 와 D 가 같은 사이클에 만나면

One more: when W and D meet in the same cycle

주어진 register file 은 상승 엣지에 쓰고, 읽기는 조합 논리다(always @(posedge clk) if (we3) rf[wa3] <= wd3). W 에 있는 명령어의 값은 그 사이클이 끝나는 엣지에 써진다. 같은 사이클 D 는 그 엣지 전에 읽으니 옛 값을 본다. 03 절 표의 "둘 건너" 경우다. 제출본은 register file 은 그대로 두고, D 의 읽기 출력 앞에 mux 를 하나씩 더 뒀다. W 가 쓰려는 레지스터면 resultW 를 바로 준다.

The given register file writes on the rising edge and reads combinationally (always @(posedge clk) if (we3) rf[wa3] <= wd3). The value of the instruction in W is written on the edge that ends the cycle; D, in that same cycle, reads before the edge and sees the old value. That's the "two in between" row in section 03's table. The submission leaves the register file alone and puts one more multiplexer on each D read output: if W is about to write that register, hand over resultW directly.

여기서 의문. register file 을 하강 엣지에 쓰면 이 mux 가 필요 없나?
그렇다. 사이클 앞 절반에 쓰고 뒤 절반에 읽으면 D 가 같은 사이클에 새 값을 본다. 대신 register file 의 쓰기와 읽기가 각각 반 주기 안에 끝나야 한다. 제출본은 주어진 register file 을 건드리지 않고 바이패스 mux 를 택했다. 이 mux 는 06 절에서 다시 쓸모가 생긴다. beq 가 D 에서 비교할 때도 같은 값을 받는다.

Question. If the register file wrote on the falling edge, would this multiplexer be unnecessary?
Yes. Write in the first half of the cycle and read in the second, and D sees the new value in the same cycle. The cost is that the write and the read each have to fit in half a period. The submission left the given register file untouched and used the bypass multiplexer instead. That multiplexer pays off again in section 06: the beq comparison in D gets the same value.

문제 2 · lw 의 값은 M 이 끝나야 생긴다 → 한 칸 멈춘다

Problem 2 · A load's value only exists after M → wait one cycle

과제 4 번의 "나머지는 stall". forwarding 으로 안 되는 경우가 하나 남는다.

Task 4's "stall for everything else": one case forwarding can't cover.

lw 의 E 는 주소를 계산할 뿐이다. 값은 M 에서 메모리를 읽어야 생기고, 그 값이 레지스터로 넘어가는 것은 M 이 끝날 때(readdataW)다. 바로 뒤 명령어가 그 값을 E 에서 쓰려면 lw 가 M 에 있을 때 이미 E 에 있어야 하는데, 그때는 값이 아직 메모리 안에 있다. forwarding 은 이미 있는 값을 건네는 것이라 이 경우는 못 푼다.

A load's E only computes the address. The value appears when M reads memory, and it moves toward the register at the end of M (readdataW). For the very next instruction to use it in E, that instruction would be in E while the load is in M, when the value is still inside memory. Forwarding hands over values that already exist, so it can't help here.

그래서 한 사이클 멈춘다. E 에 lw 가 있고(memtoregE, regwriteE), D 의 명령어가 그 lw 가 쓸 레지스터(rtE)를 읽으면 lwstallD = 1. 그러면 stallF 와 stallD 가 PC 와 IF/ID 를 붙잡고, flushE 가 다음 사이클 ID/EX 에 빈 명령어(bubble)를 넣는다. 한 사이클 뒤 lw 는 W 에 있고, 기다리던 명령어는 E 에서 W 의 값을 forwarding 으로 받는다.

So the pipeline waits one cycle. If a load is in E (memtoregE, regwriteE) and the instruction in D reads the register the load will write (rtE), lwstallD = 1. Then stallF and stallD hold PC and IF/ID, and flushE puts an empty instruction (a bubble) into ID/EX the next cycle. One cycle later the load is in W, and the waiting instruction picks up W's value in E by forwarding.

usesRsD · usesRtD 는 D 의 명령어가 그 필드를 정말 읽는지다. lw 와 addi 는 rt 를 쓰는 쪽이라 읽지 않고, j 는 둘 다 안 읽는다. 이걸 안 보면 필드 값이 우연히 같을 때 필요 없는 stall 이 생긴다.

문제 3 · beq 를 판정하기 전에 다음 명령어를 이미 가져왔다 → D 에서 판정하고 하나 버린다

Problem 3 · The next instruction is fetched before beq is decided → decide in D and throw one away

과제 4 번의 flush. jump 도 같은 길을 쓴다.

Task 4's flushing. Jumps use the same path.

pipeline 은 매 사이클 다음 명령어를 가져온다. beq 가 taken 인지는 두 레지스터를 비교해야 아는데, 그 비교가 끝나기 전에 F 는 이미 바로 다음 주소의 명령어를 가져왔다. taken 이면 그 명령어는 실행되면 안 된다. 상태를 바꾸기 전에 버리는 것을 flush 라고 한다.

The pipeline fetches the next instruction every cycle. Whether a beq is taken is known only after comparing two registers, and by then F has already fetched the instruction at the next address. If the branch is taken, that instruction must not run. Throwing it away before it changes anything is a flush.

몇 개를 버리느냐는 어디서 판정하느냐다. 주어진 single-cycle 은 ALU 의 zero 로 판정했다. pipeline 에서 그대로 E 에서 판정하면 그 사이 D 와 F 에 들어온 둘을 버려야 하고, M 까지 미루면 셋이다. 제출본은 비교기와 분기 목적지 adder 를 D 로 옮겼다. 그러면 버리는 것은 F 에 있는 하나뿐이다.

How many get thrown away depends on where the branch is decided. The given single-cycle design used the ALU's zero. Deciding in E in the pipeline would mean discarding the two that entered D and F meanwhile; deferring to M, three. The submission moved the comparator and the branch target adder into D, so only the one instruction in F is lost.

D 에서 비교하면 생기는 새 기다림

D 에서 비교하려면 두 피연산자가 D 에 와 있어야 한다. 바로 앞 명령어(E)나 그 앞(M)이 그 레지스터를 쓰는 중이면 값이 D 로 올 길이 없다. forwarding mux 는 E 입구에만 있기 때문이다. 제출본은 그 경우 branchstallD 로 기다리게 한다. W 에 있는 값은 바이패스로 받으니 기다릴 필요가 없다.

To compare in D, both operands have to be available in D. If the instruction right before (in E) or the one before that (in M) is writing one of those registers, there is no path for the value to reach D: the forwarding multiplexers sit only at the entrance of E. The submission makes the branch wait with branchstallD in that case. A value in W comes through the bypass, so no wait is needed.

대가 · 판정을 당긴 만큼 클럭이 길어진다

The price · Deciding earlier makes the clock longer

hazard 를 막는 회로가 critical path 가 되고, 그 대신 IPC 가 오른다.

The hazard circuitry becomes the critical path; in exchange, IPC goes up.

03~06 절의 해결책은 공짜가 아니다. 넣은 회로가 클럭 주기를 정한다. 리포트는 critical path 를 IF/ID → instrD → register file 읽기 → 비교기(=) → zero → 분기 판정(takeBranchD) → 분기 mux → jump mux → PC 로 적었고, arrival 은 약 1.00 ns, 1 ns 목표에서 slack 약 -0.02 라고 썼다. D 에서 판정하려고 들인 경로다.

The fixes in sections 03 to 06 aren't free; the circuitry they add sets the clock period. The report gives the critical path as IF/ID → instrD → register file read → comparator (=) → zero → branch decision (takeBranchD) → branch multiplexer → jump multiplexer → PC, with an arrival of about 1.00 ns and a slack of about -0.02 against a 1 ns target. valid 비트: 빈 칸과 버린 칸

Valid bits: empty slots and discarded slots

stall 은 E 에 bubble 을 넣고, flush 는 D 를 비운다. 빈 칸에도 레지스터의 비트는 남아 있으니, 그 칸이 레지스터나 메모리를 쓰거나 forwarding 에 끼어들면 안 된다. 제출본은 단계마다 validD · validE · validM · validW 를 두고, 상태를 바꾸는 신호를 전부 그 비트로 막는다. 예를 들어 ID/EX 로 넘길 때 regwriteE <= validD && regwrite, memwriteE <= validD && memwriteD 다. forwarding 과 stall 조건도 valid 를 본다.

A stall puts a bubble into E, and a flush empties D. The register bits are still there in an empty slot, so the slot must not write a register or memory, or take part in forwarding. The submission keeps validD, validE, validM, validW per stage and gates every state-changing signal with them. Passing into ID/EX, for example: regwriteE <= validD && regwrite, memwriteE <= validD && memwriteD. The forwarding and stall conditions check valid too.

flushE 는 ID/EX 의 값과 제어 신호를 0 으로, validE 를 0 으로 만든다. redirectD 는 IF/ID 의 instrD, pcplus4D, validD 를 0 으로 만든다(06 절 발췌). 트레이스에서 - 로 보이는 칸이 이것이다.

Part 2 · MULADD · 피연산자가 셋

Part 2 · MULADD · Three operands

레지스터 셋을 읽는 명령어를, 둘만 읽게 만들어진 pipeline 에 넣는다.

An instruction that reads three registers, in a pipeline built to read two.

MULADD 는 레지스터 셋을 읽는다. rs, rt, 그리고 쓸 레지스터 rd 의 지금 값. 주어진 register file 은 읽기 포트가 둘이다. 길은 셋이었다. (1) 읽기 포트를 하나 더 단다. (2) 두 사이클에 나눠 읽는다(stall 하나). (3) 셋째 값을 다른 곳에 미리 둔다. 제출본은 (1) 을 골랐다. 한 사이클에 끝나고, 셋째 값도 다른 두 값과 같은 길을 걷게 하면 hazard 처리를 그대로 재사용할 수 있기 때문이다.

MULADD reads three registers: rs, rt, and the current value of rd, the one it writes. The given register file has two read ports. There were three ways: (1) add a third read port, (2) read over two cycles (one stall), (3) keep the third value somewhere else in advance. The submission took (1): it finishes in one cycle, and if the third value walks the same path as the other two, the hazard handling can be reused as it is.

그림 읽기. register file 에 셋째 읽기 포트 ra3 가 생기고 rd 필드가 주소다. 그 출력은 rd3D(바이패스 뒤), ID/EX 의 rd3E, forwardCE 가 고르는 mux 를 지나 ALU 의 셋째 입력 c 가 된다. ALU 에는 연산 011 이 생겼다. a * b + c. controller 는 opcode 011100 을 RegWrite·RegDst 1, ALUOp 11 로 해독하고, aludec 이 ALUOp 11 을 011 로 바꾼다. 곱은 SystemVerilog 의 32 비트 곱셈이라 아래 32 비트만 남는다. 설명서의 가정 그대로다.

Reading the figure. The register file gets a third read port, ra3, addressed by the rd field. Its output becomes rd3D (after the bypass), then rd3E in ID/EX, then goes through the mux chosen by forwardCE to the ALU's third input, c. The ALU gets operation 011: a * b + c. The product is a 32-bit SystemVerilog multiply, so only the low 32 bits survive, exactly the handout's assumption.

셋째 읽기 포트는 명령어가 무엇이든 rd 필드로 읽는다. MULADD 가 아닌 R 형식이면 rd 는 곧 써질 레지스터라 아직 아무도 안 쓴 값이 많고, 시뮬레이션에서는 X 로 보인다. perfmon 트레이스의 cycle 3, 6, 7 이 그렇다. ALU 는 연산 011 일 때만 c 를 쓰니 결과에는 상관없다. 다만 데모에서 그 줄을 띄우면 놀랄 만하다.

The third read port reads the rd field whatever the instruction. For an R-format instruction that isn't MULADD, rd is the register about to be written, often one nobody has written yet, and simulation shows X. Cycles 3, 6 and 7 of the perfmon trace are examples. The ALU only uses c for operation 011, so results are unaffected, but the row looks alarming if it's on screen at the demo.

2-state · 4-state
자료형이 가질 수 있는 값의 가짓수. 4-state는 0 1 x z, 2-state는 0 1뿐이다. logic·wire·reg가 4-state, bit·int가 2-state다. 설계에 2-state를 쓰면 리셋 안 된 flop이 x 대신 0으로 보여서 버그가 시뮬레이션을 통과한다.
How many values a type can take. Four-state is 0 1 x z; two-state is just 0 1. logic, wire and reg are four-state; bit and int are two-state. Use two-state in a design and an unreset flop reads 0 instead of x, so the bug passes simulation.

A

Agent
Testbench에서 Driver와 Monitor를 (인터페이스와 함께) 한 부품으로 묶은 것. BFM, Transactor와 같은 것을 가리킨다. UVM에서 uvm_agent라서 이 이름이 가장 표준적이다. 재사용의 단위다. APB agent를 한 번 만들면 APB를 쓰는 어떤 DUT에도 붙는다.
In a testbench, the driver and monitor bundled into one component along with the interface. The same thing as a BFM or transactor. UVM calls it uvm_agent, which makes this the standard name. It is the unit of reuse: build an APB agent once and it plugs into any DUT that speaks APB.
Lecture 2 · 18
always_comb · always_ff
SystemVerilog가 추가한 의도를 밝히는 always 블록. always_comb은 조합 논리를, always_ff는 flip-flop을 만들 셈이라고 도구에게 선언한다. 어긋나면 경고가 나온다. 선언한다고 저절로 그렇게 되지는 않는다. always_ff에도 @(posedge)와 non-blocking 대입은 직접 써야 한다.
SystemVerilog blocks that declare your intent. always_comb says you meant combinational logic and always_ff says you meant flip-flops, and the tool warns when the code disagrees. Declaring does not make it so: you still write the @(posedge) and the non-blocking assignments yourself.
Lecture 3 · 03
Analysis · vlogan · vhdlan · syscan
시뮬레이터 compile 의 첫 단계. 소스 파일을 하나씩 읽어 문법을 검사하고 결과를 logical library 에 넣는다. 언어마다 분석기가 다르다. Verilog 는 vlogan, VHDL 은 vhdlan, SystemC 는 syscan. 순수 Verilog / SystemVerilog 면 이 단계를 따로 부르지 않는다. 그래서 2-step flow 가 성립한다.
The first compile phase. It reads the source files one at a time, checks their syntax and files the result into a logical library. Each language has its own analyser: vlogan for Verilog, vhdlan for VHDL, syscan for SystemC. Pure Verilog or SystemVerilog never invokes this stage separately, which is what makes the 2-step flow possible.
Lab 0 · 02
AOI
And-Or-Invert
Standard cell library에 들어 있는 복합 논리 cell. AND와 OR와 반전을 한 cell 안에서 처리한다. 게이트를 따로 쓰는 것보다 작고 빠른 경우가 많아 합성 도구가 즐겨 쓴다.
A compound logic cell found in standard cell libraries, doing AND, OR and inversion inside one cell. It is often smaller and faster than separate gates, so synthesis tools reach for it.
Lecture 2 · 06
ASIC
Application Specific Integrated Circuit
한 가지 용도로 고정해서 만든 칩. 만들고 나면 회로가 안 바뀐다. FPGA의 반대편이다. 틀리면 되돌릴 수 없다는 이 한 문장이 이 과목의 verification 전체를 설명한다.
A chip frozen to one purpose; once made, the circuit does not change. The opposite of an FPGA. It cannot be taken back once it is wrong, and that one sentence explains this course's entire attitude to verification.
Lecture 1 · 01
Assertion
설계가 반드시 보여야 하거나 절대 보이면 안 되는 동작을 코드로 명시한 것. 결정적인 성질은 "항상 켜져 있다"는 것이다. 어떤 테스트를 돌리든 계속 감시한다. 예: assert property (@(posedge clk) !(grant0 & grant1));
Code that states behaviour the design must, or must never, exhibit. The decisive property is that it is always on: it keeps watching no matter which test is running. For example assert property (@(posedge clk) !(grant0 & grant1));

Autoconnect · .*
자식 module의 포트를 이름이 같은 신호에 자동으로 연결하는 축약. mod x (.*); 한 줄이 .a(a), .b(b), .c(c)를 대신한다. 이름과 폭이 둘 다 맞아야만 동작하고, 안 맞으면 컴파일 에러다. 연결이 코드에 안 보여서 팀마다 사용 정책이 갈린다.
A shorthand that wires a child module's ports to same-named signals automatically. One mod x (.*); replaces .a(a), .b(b), .c(c). Names and widths must both match, and a mismatch is a compile error. Because the connections are invisible in the code, teams differ on whether to allow it.
Lecture 3 · 04
automatic
task와 function을 호출할 때마다 지역 변수를 새로 만들게 하는 키워드. module 안에서는 기본이 static이라 모든 호출이 변수 한 벌을 공유한다. 같은 task가 fork로 동시에 두 번 돌면 서로를 덮어쓴다. 그래서 testbench의 task·function에는 거의 항상 붙인다.
A keyword that makes a task or function allocate fresh locals on every call. Inside a module the default is static, so every call shares one set of variables. Run the same task twice at once under a fork and they overwrite each other. Put it on nearly every testbench task and function.
Lecture 3 · 14

B

Back-End
설계 흐름에서 모양과 물성을 다루는 구간. Place and Route, Fabrication, Board/Product. 구별 기준은 산출물이 파일이면 front-end, 모양이면 back-end. Synthesis는 경계에 걸쳐 있다.
The part of the flow that deals in shapes and physics: place and route, fabrication, board and product. The test is simple: file output means front end, shape output means back end. Synthesis straddles the line.
Lecture 1 · 03
BDD · ROBDD
(Reduced Ordered) Binary Decision Diagram
Boolean 함수를 표현하고 조작하는 자료구조. ROBDD는 canonical하다. 즉 같은 함수는 반드시 같은 모양이 된다. 그래서 두 ROBDD를 비교하면 두 함수가 같은지가 즉시 증명된다. Equivalence checking의 바탕이다. 조합 논리에만 쓴다.
A data structure for representing and manipulating boolean functions. ROBDDs are canonical: the same function always produces the same shape, so comparing two of them immediately proves whether the functions are equal. It underpins equivalence checking. Combinational logic only.
Lecture 2 · 15
BFM
Bus Functional Model
Agent와 같은 것. Driver와 Monitor를 묶은 testbench 부품을 부르는 다른 이름이다. 회사와 팀마다 Agent, BFM, Transactor 중 아무거나 쓴다.
The same thing as an agent: another name for the testbench component that bundles a driver and a monitor. Companies and teams use agent, BFM and transactor interchangeably.
Lecture 2 · 18
BIST
Built-In Self-Test
칩 안에 스스로를 테스트하는 회로를 미리 넣어두는 것. DFT 기법 중 하나다. 바깥에서 핀으로만 접근할 수 있는 manufacturing test의 한계를 안쪽에서 보완한다.
Building circuitry that tests the chip itself into the chip. One of the DFT techniques, it compensates from inside for the fact that manufacturing test can only reach the pins.
Lecture 2 · 10
bit
2-state 자료형. 0과 1만 갖고 시뮬레이션 시작 시 0이다. 시뮬레이션이 빠르고 메모리를 덜 먹는다. 슬라이드가 "Use only in verification"이라고 못 박았다. 설계에 쓰면 x가 안 보여서 리셋 누락 같은 버그를 놓친다. 반대말은 logic.
The two-state type: only 0 and 1, and it starts simulation at 0. Faster and lighter than four-state. The slide is blunt about it: "Use only in verification." In a design it hides x and lets missing-reset bugs through. Its opposite is logic.
Lecture 3 · 02
Bring-up
새 칩이 처음 도착했을 때 동작하게 만들어가는 과정. 전원을 넣고 클럭이 도는지부터 확인한다. NVIDIA에는 이 단계에 붙는 고유 이름이 없어서 그냥 bringup이라고 부른다고 슬라이드가 적어놨다. Testbench 쪽에서도 "testbench and DUT bringup"이라는 표현을 같은 뜻으로 쓴다.
The process of getting a brand new chip to do anything at all, starting from whether the clock runs when power goes in. The slides note that NVIDIA has no specific name for this stage and just calls it bringup. The same word is used on the testbench side, as in "testbench and DUT bringup".
Lecture 1 · 10
Bus Semantics
여러 드라이버가 한 선을 공유하되 한 번에 하나만 몰기로 약속한 것. 나머지는 z로 물러난다. 슬라이드 24의 "multiple driver 금지" 규칙에서 유일하게 허용되는 예외이고, 조건은 "explicitly", 즉 실수가 아니라 의도적으로 그렇게 설계했을 때다. 이때 신호는 logic이 아니라 wire여야 한다.
Several drivers sharing one line on the agreement that only one drives at a time, the rest sitting back at z. It is the one exception to the "no multiple drivers" rule on slide 24, and the condition is "explicitly": designed that way on purpose, not by accident. The signal then has to be a wire, not a logic.
Lecture 3 · 17

C

Canonical
표현이 하나뿐이라는 뜻. 중복도 반복도 애매함도 없다. 어떤 표현이 canonical이면, 두 대상이 같은지를 모양만 비교해서 판정할 수 있다. ROBDD가 그렇다.
There is exactly one representation. No redundancy, no repetition, no ambiguity. When a representation is canonical, you can decide whether two things are equal by comparing shapes alone. ROBDDs are the example.
Lecture 2 · 15
CDC
Clock Domain Crossing
한 클럭 도메인의 신호가 비동기인 다른 도메인의 flip-flop에서 샘플링되는 지점. 설계할 때 이미 생기고 실리콘에서만 실패로 드러나며, STA는 이 경계를 아예 보지 않는다.
The point where a signal from one clock domain is sampled by a flop in a different, asynchronous domain. It is created at design time but only fails in silicon, and STA never looks here at all.
Lecture 4 · 06
Checker
DUT가 제대로 동작하는지 확인하고 불법적인 일이 벌어지면 오류를 띄우는 testbench 부품. 두 층이 있다. 신호 수준(assertion)과 동작 수준(scoreboard). 검증의 세 기둥 중 하나.
The testbench component that confirms the DUT behaves correctly and raises an error when something illegal happens. It has two layers: signal level, meaning assertions, and behavioural, meaning scoreboards. One of the three pillars of verification.
Lecture 2 · 16
Circular Buffer
끝에 닿으면 처음으로 되돌아오는 고정 크기 저장소. FIFO 의 알맹이다. 되돌아오는 데 별도 로직이 필요 없다는 것이 요점으로, 주소 비트 수만큼만 남기고 자르면 덧셈이 저절로 wrap 한다. 대신 가득 참과 비어 있음이 같은 주소에서 만나는 문제가 생기고, 그 답이 wrap bit 다.
A fixed-size store whose addresses run back to the start at the end. It is the core of a FIFO. The point is that wrapping needs no logic of its own: truncate to the address width and the arithmetic wraps by itself. The cost is that full and empty meet at the same address, which is what the wrap bit exists to resolve.
Lecture 5 · 06
Clock Gating
회로에서 지금 쓰지 않는 부분에 클럭을 끊어 전력을 아끼는 기법. 클럭이 안 도는 flip-flop은 동적 전력을 거의 안 쓴다. 전원을 통째로 끄는 power gating과 다르다.
Saving power by stopping the clock to parts of the circuit that are idle. A flip-flop with no clock burns almost no dynamic power. Distinct from power gating, which shuts the supply off entirely.
Lecture 2 · 10
Clock Skew
같은 클럭이 서로 다른 flip-flop에 도착하는 시각의 차이(Tskew). RTL이 아니라 clock tree synthesis 단계에서 생기고 physical design이 관리한다. setup 쪽에서는 여유를 늘려주고 hold 쪽에서는 깎아먹는다.
The difference in arrival time of the same clock at two flops (Tskew). Created during clock tree synthesis, not RTL, and managed by physical design. It helps setup margin but eats into hold margin.
Lecture 4 · 01
Clock-to-Q Delay
클럭 엣지가 들어온 뒤 flip-flop 출력 Q가 실제로 바뀌기까지 걸리는 시간(Tcq). setup·hold와 달리 지켜야 할 최소치가 아니라 경로 지연에 그냥 더해지는 값이라, "clock-to-Q 위반"이라는 것은 없다.
How long after a clock edge a flop's Q output actually changes (Tcq). Unlike setup and hold, it is not a minimum to meet, just a number added to the path delay, so there is no such thing as a clock-to-Q violation.
Lecture 4 · 01
CNF · POS
Conjunctive Normal Form · Product Of Sums
Boolean 식을 OR로 묶은 항들을 AND로 이어붙인 형태로 정규화한 것. 두 이름이 같은 것을 가리킨다. SAT 풀이의 입력 형식이다.
A boolean expression normalised into a conjunction of disjunctions, that is, ANDs of ORs. Two names for one form. It is the input format for SAT solving.
Lecture 2 · 15
Code Coverage
코드의 줄·분기·상태·신호가 실행되거나 바뀌었다는 것을 세는 커버리지. Line, Branch, State Machine, Toggle coverage가 있다. 한계: 실행된 것과 옳은 것은 다르고, 코드 줄에 대응하지 않는 시나리오는 셀 수 없다. Functional coverage가 뒤쪽을 보완한다.
Coverage that counts whether lines, branches, states and signals were executed or toggled. Line, branch, state machine and toggle coverage. Its limits: executed is not correct, and scenarios that correspond to no single line cannot be counted. Functional coverage covers the latter.
Lecture 2 · 16
Constrained Random
랜덤 자극을 넣되 constraint로 불법 입력을 걸러내는 방식. 아무 값이나 넣으면 설계가 애초에 대응할 필요 없는 상황에서 실패하고, 그건 버그가 아니다. 값뿐 아니라 타이밍과 순서도 randomize 하는 것이 핵심이다.
Random stimulus with constraints filtering out illegal inputs. Throw anything in and the design fails in a situation it was never required to handle, which is not a bug. The important part is randomising timing and ordering, not just values.
Lecture 2 · 16
Coverage
DUT를 얼마나 잘 두들겼는지를 정량화한 것. 점수가 높을수록 stimulus의 품질이 높다. 실패한 테스트의 커버리지는 세지 않는다. Code coverage와 functional coverage 두 갈래가 있다.
A quantitative measure of how well the DUT was exercised. A higher score means better stimulus. Never count coverage from a failing test. It splits into code coverage and functional coverage.
Lecture 2 · 16
CTL · LTL
Computation Tree Logic · Linear Temporal Logic
Temporal logic의 종류. 순차적 동작을 분석 가능한 형태로 표현하려고 쓴다. AG(req → F ack)는 "어떤 경로에서든(A), 언제나(G), req가 뜨면 언젠가(F) ack가 뜬다", 즉 요청은 반드시 응답받는다는 뜻이다.
Kinds of temporal logic, used to express sequential behaviour in an analysable form. AG(req → F ack) reads: on all paths (A), globally (G), if req rises then finally (F) ack rises. In plain words, every request gets answered.
Lecture 2 · 15

D

Data Path
값이 실제로 흘러가며 변형되는 곳. 산술 회로, memory, storage가 여기 있다. Control path와 짝을 이룬다. Data path 버그는 값이 틀리고, control path 버그는 타이밍이나 순서가 틀린다. 뒤쪽이 훨씬 잡기 어렵다.
Where values actually flow and get transformed: arithmetic circuits, memory, storage. It pairs with the control path. A data path bug gives a wrong value; a control path bug gives wrong timing or ordering, and the latter is far harder to catch.
Lecture 2 · 02
.ddc · .db · .lib
DC 주변 확장자 셋. 계보가 둘로 갈린다. .lib 은 technology library 의 사람이 읽는 ASCII 원본이고, Library Compiler 가 그것을 컴파일하면 DC 가 실제로 읽는 .db 가 된다. 여기까지가 library 계보다. .ddc 는 완전히 다른 것으로, DC 메모리 안의 설계를 저장하는 형식이다. 예전에는 설계도 db 로 저장했기 때문에 오래된 스크립트에서는 .db 가 설계 자리에 나온다. 확장자만 보고 판단하지 말고 그 줄이 무엇을 읽고 쓰는지를 볼 것.
Three extensions that live around DC, in two separate lineages. .lib is the human-readable ASCII source of a technology library, and Library Compiler turns it into the .db that DC actually reads. That is the library lineage. .ddc is something else entirely: the format for saving the design held in DC memory. Designs used to be saved as db too, so in older scripts you will find .db where a design belongs. Do not judge by the extension; read what the line is loading or writing.
Lab 0 · 11
Design Compiler · DC
Design Compiler
Synopsys 의 합성 도구. RTL 을 읽어 technology library 의 gate 로 매핑하고 gate-level netlist 를 내놓는다. 명령줄 옵션으로 모는 VCS 와 달리 Tcl 스크립트로 몬다. 합성이 한 번에 끝나는 일이 아니라 library 읽기, 제약 걸기, compile, 리포트 뽑기가 이어지는 절차이기 때문이다.
Synopsys's synthesis tool. It reads RTL, maps it onto gates from a technology library, and emits a gate-level netlist. Unlike VCS, which you steer with command-line options, you steer DC with a Tcl script, because synthesis is not one shot but a sequence: read libraries, apply constraints, compile, report.
Lab 0 · 11
DFx · DFT · DFM · DFD
Design For Testability / Manufacturability / Debuggability
"Design For __"의 총칭. 전부 본래 기능과 무관한데 나중을 위해 미리 넣어두는 것이고, 그래서 전부 면적과 타이밍을 잡아먹는다. 나중에는 못 넣기 때문에 미리 넣는다. DFT의 T는 Testability이지 Test가 아니다. 다만 Freescale/NXP와 NVIDIA에서는 manufacturing test 조직 전체를 DFT라고 부른다.
An umbrella for "design for __". All of them are things unrelated to the function, put in now for later, and all of them cost area and timing. They go in early because later is not an option. The T in DFT is testability, not test, although Freescale, NXP and NVIDIA use DFT for the whole manufacturing test organisation.
Lecture 2 · 10 · Lecture 1 · 13
DLL
Delay-Locked Loop
지연 소자로 입력 클럭의 위상만 맞추는 회로. 주파수는 바꾸지 않는다. DDR 메모리 인터페이스처럼 위상 정렬만 필요할 때 쓴다.
A loop of delay elements that aligns only the phase of an input clock. It never changes the frequency. Used where only phase alignment is needed, such as DDR memory interfaces.
Lecture 4 · 02
DPI
Direct Programming Interface
SystemVerilog에서 C/C++ 함수를 직접 부르고 반대로 불리게 하는 인터페이스. 검증에서 C로 짠 참조 모델(golden model)을 testbench에 붙일 때 쓴다. 강의계획서가 "model based verification (C model integration using PLI/DPI)"으로 적어둔 것이 이것이고, Lab 4의 주제 중 하나다.
The SystemVerilog interface for calling C and C++ functions directly, and being called back. In verification it is how a reference model written in C gets attached to a testbench. The syllabus lists it as "model based verification, C model integration using PLI/DPI", and it is one of the topics in Lab 4.

Directed Test
시나리오를 사람이 정해서 정확히 그것만 만들어내는 테스트. 좋은 점: 아주 잘 제어된다. 나쁜 점: 몇 개나 쓸 수 있겠나. 가능한 시나리오를 사람이 다 생각해낼 수 없다. 그래서 randomization과 같이 쓴다.

Double-FF Synchronizer
받는 쪽 도메인에 flip-flop 두 개를 연달아 붙여, 첫 flop이 metastable해도 두 번째가 잡을 때쯤엔 대개 정착해 있게 만드는 구조. 한 비트(또는 gray coded 버스)를 CDC로 넘길 때 가장 먼저 쓰는 기본 수단이다.
Two flops back to back in the receiving domain, so that even if the first goes metastable, the value has usually settled by the time the second samples it. The default first choice for crossing one bit, or a gray-coded bus, over a CDC.

Dual-Port Memory

Memory that takes separate read and write addresses, so one place can be read while another is written in the same cycle. Dual-port, two-port and true dual-port are three different things.

Equivalence Checking

FIFO
First-In, First-Out
먼저 들어온 데이터가 먼저 나오는 버퍼. 소프트웨어의 queue 와 같은 개념인데 하드웨어에서는 거의 항상 FIFO 라고 쓴다. 속도가 안 맞는 두 블록 사이를 잇는 데 쓰지만 평균 속도를 바꿔주지는 않는다. 흡수하는 것은 순간의 burst 이고, 평균이 안 맞으면 깊이를 늘려도 결국 넘치거나 마른다. LIFO(stack) 와 반대이고, 그냥 "buffer" 는 순서를 안 지킬 수도 있다.
A buffer where the first item in is the first item out. The same idea software calls a queue, but hardware almost always says FIFO. It joins two blocks whose rates disagree, yet it does not change the average rate: it absorbs bursts, and if the averages differ it will eventually overflow or run dry however deep it is. The opposite of a LIFO, a stack, and something merely called a buffer need not preserve order.

Solving the verification problem with mathematics: express the design as a formula and prove it holds under constraints. Also called static verification. Exhaustive, but it does not scale, because of the state explosion problem. The slides state outright that it is not a focus of this course. The three techniques are equivalence checking, model checking and theorem proving.

Standard cell library의 변형들. VT는 트랜지스터가 켜지는 문턱 전압이다. HVT는 느리지만 누설이 적고, LVT는 빠르지만 누설이 많다. HP(High Performance)와 LP(Low Power)도 같은 축의 다른 이름이다. 도구가 급한 경로에만 LVT를 쓰고 나머지는 HVT로 채우는 식으로 트레이드오프를 실행한다.

Latch Inference
조합 논리를 쓸 셈이었는데 합성 도구가 latch를 만들어버리는 것. if에 else가 없거나 case에 default가 없으면 "그 경우엔 이전 값을 유지"가 되고, 유지하려면 저장 소자가 필요하다. latch는 scan chain에 안 들어가서 테스트가 안 되므로 대부분의 설계 규칙이 금지한다. 시뮬레이션은 대개 통과하고 합성 리포트나 lint에서 뒤늦게 드러난다.
You meant combinational logic and the tool built a latch. An if with no else, or a case with no default, means "otherwise keep the old value", and keeping a value needs storage. A latch does not join the scan chain, so it cannot be tested, and most design rules ban it. Simulation usually passes; it surfaces late, in the synthesis report or from lint.

.lib · .lef · .db
Tech library 파일 형식. .lib는 타이밍과 전력으로 synthesis와 STA가 쓰고, .lef는 물리 layout 정보로 place and route가 쓰고, .db는 .lib의 바이너리 버전이다. 현장에서는 확장자만으로 부른다.
Tech library file formats. .lib holds timing and power for synthesis and STA, .lef holds physical layout for place and route, and .db is the binary form of .lib. People refer to them by extension alone.
Lecture 2 · 06
Lint
코드를 돌리지 않고 읽어서 가이드라인 위반을 찾는 정적 분석. 도구는 Synopsys Spyglass. 잡는 것: 도달할 수 없는 코드, 명명 규칙, blocking과 non-blocking 혼용, 합성 불가 구문, 다중 driver, 의도치 않은 latch. 스타일 지적이 아니다. 절반 이상이 실물이 코드와 다르게 동작하게 만드는 원인이다. 다만 lint는 verification이 아니다. "규칙을 지키는가"만 볼 뿐 "사양대로인가"는 못 본다.
Static analysis that reads the code without running it and finds guideline violations. The tool named is Synopsys Spyglass. It catches unreachable code, naming conventions, mixed blocking and non-blocking assignments, un-synthesisable constructs, multiple drivers and unintended latches. These are not style nits: more than half of them cause the physical part to behave differently from the code. But lint is not verification; it only asks whether rules are followed, never whether the design matches the spec.
Lecture 2 · 08
logic
SystemVerilog가 wire와 reg의 혼란을 끝내려고 내놓은 4-state 자료형. assign의 좌변으로도, always 블록 안에서도 쓴다. reg의 새 이름이 아니다. 진짜 변화는 "variable도 continuous assignment를 하나까지 받을 수 있게" 규칙이 풀린 것이다. 드라이버가 둘이면 컴파일 에러이고, 그래서 다중 드라이버가 필요한 tristate 버스에는 여전히 wire를 쓴다.
The four-state type SystemVerilog introduced to end the wire versus reg question. It works on the left of an assign and inside an always block alike. It is not reg renamed. The real change is that the rules relaxed so a variable may take one continuous assignment. Two drivers is a compile error, which is why a tristate bus still needs a wire.

Library Compiler

link_library
DC 변수. reference 를 해석할 곳을 가리킨다. reference 란 설계 안에 인스턴스로 박혀 있지만 정의가 여기 없는 gate, block, sub-design 이다. 이미 합성된 netlist 를 읽을 때 그 안의 셀 이름을 이걸로 찾는다. 기본값이 존재하지 않는 파일(your_library.db)이라 안 잡아주면 반드시 경고가 뜬다. 그런데 그 경고는 report 나 compile 을 중단시키지 않는다. 명령은 끝까지 돌고 리포트도 나오지만 숫자가 의미가 없다. target_library 와 갈리는 기준: 읽을 때 쓰면 link.
A DC variable naming where references get resolved. A reference is any gate, block or sub-design instantiated in the design whose definition lives elsewhere; this is what makes sense of cell names inside a netlist you read in. Its default is a file that does not exist (your_library.db), so leaving it alone guarantees warnings. Those warnings do not abort the report or compile: the command finishes and a report appears, but its numbers mean nothing. The rule that separates it from target_library: reading uses link.

Logical Library
분석 결과를 담아두는 저장소에 붙인 이름. 실제 디렉토리가 아니라 그것을 가리키는 별명이고, 어느 디렉토리인지는 synopsys_sim.setup 이 이름 : 경로 한 줄로 정한다. Verilog 에는 이 개념이 아예 없다. VHDL 이 들어올 때 따라 들어온다. Technology Library 와는 아무 관계가 없다.
A name for the store that analysed results go into. Not a directory but an alias for one, and synopsys_sim.setup decides which directory with a single name : path line. Verilog has no such concept at all; it arrives with VHDL. It has nothing to do with a technology library.
Lab 0 · 04
LRM
Language Reference Manual
언어의 표준 문서. SystemVerilog의 것은 IEEE 1800이다. 시뮬레이터 벤더는 구현을 마음대로 해도 되지만 LRM은 지켜야 한다. 도구마다 결과가 갈릴 때 최종 심판이다. 단, LRM이 정하지 않은 구간에서는 도구마다 달라도 둘 다 맞다. 그래서 그런 코드는 안 쓰는 게 관행이고 lint가 잡아준다.
The standard document for a language; for SystemVerilog it is IEEE 1800. A vendor may implement the simulator however it likes but must obey the LRM. It is the final referee when tools disagree. Where the LRM deliberately leaves things undefined, though, two tools can differ and both be right, which is why nobody writes such code on purpose and lint flags it.
Lecture 2 · 14

M

Manager · Subordinate
AMBA 스펙이 master와 slave를 대체하려고 쓰는 용어. 뜻은 완전히 같다. 트랜잭션을 시작하는 쪽이 Manager(=master), 응답하는 쪽이 Subordinate(=slave)다. 기존 코드와 툴 옵션에는 여전히 master/slave가 남아 있으므로 둘 다 알아야 한다. 강의 슬라이드는 벤더 트레이닝 자료라 옛 이름을 쓴다.
The terms recent AMBA specifications use in place of master and slave. The meaning is identical: the side that starts a transaction is the Manager, the side that responds is the Subordinate. Existing code and tool options still say master and slave, so you need both. The lecture slides come from vendor training and use the older names.
Lecture 3 · 10
Mask
웨이퍼에 패턴을 찍기 위한 판. Place and Route가 끝나면 layout이 나오고 그것이 mask가 된다. Base layer는 트랜지스터 자체를 만드는 아래쪽 층으로, 고치면 mask를 거의 다 새로 만들어야 한다. Metal layer는 위쪽 배선 층으로, 여기만 고치는 metal-only ECO는 훨씬 싸고 빠르다.
The plates used to print patterns onto a wafer. Place and route produces a layout, and that layout becomes the masks. The base layers form the transistors themselves, and touching them means remaking nearly all the masks. The metal layers are the upper wiring, and a metal-only ECO that touches just those is far cheaper and faster.
Lecture 1 · 07
Metastability
flip-flop의 D 입력이 setup/hold 윈도우 안에서 바뀌어 Q가 0도 1도 아닌 불확정 상태로 한동안 머무는 현상. 같은 클럭 도메인 안에서는 안 생기고, 동기화 없이 넘어온 비동기 신호에서만 생긴다. glitch와는 다른 현상이다.
A flop's D input changes inside the setup/hold window, and Q sits undecided, neither 0 nor 1, for a while. It cannot happen inside one clock domain, only where an unsynchronised asynchronous signal walks straight in. Not the same thing as a glitch.
Lecture 4 · 06
Microarchitecture
Architecture가 정의한 동작을 register, memory, gate, control path, data path로 구현한 구체적 형태. Architecture가 "무엇을"이라면 microarchitecture는 "어떻게"다. 같은 architecture를 여러 microarchitecture로 만들 수 있다. x86 하나에 Intel과 AMD의 서로 다른 microarchitecture가 붙는 것이 그 예다.
The behaviour defined by an architecture, made concrete with registers, memories, gates, control paths and data paths. Architecture says what; microarchitecture says how. One architecture can carry many microarchitectures, as x86 carries quite different ones at Intel and AMD.

Model Checking
주어진 모델(설계)이 주어진 제약 아래 주어진 property를 만족하는지 확인하는 formal 기법. Property checking이라고도 한다. 유한 상태 모델에 대해 temporal logic 식을 검사한다. 보통 시뮬레이션 기반 design verification을 보조하는 데 쓴다.
A formal technique that checks whether a given model satisfies a given property under given constraints. Also called property checking. It evaluates temporal logic formulas on finite state models, and is usually used to aid simulation based design verification.
Lecture 2 · 15
modport
module port
하나의 interface를 어느 쪽에서 보느냐에 따라 신호 방향을 정해준 관점. 같은 req 신호가 한쪽에는 output, 다른 쪽에는 input이 된다. 막으려는 것은 multi-driver다. 방향이 없으면 두 module이 같은 신호를 몰아 x가 뜨는데, modport가 있으면 컴파일 시점에 에러가 난다. 연결하는 쪽이 아니라 받는 쪽 포트 선언에서 고른다.
A view of one interface that fixes signal directions for the side you stand on. The same req is an output on one side and an input on the other. It exists to stop multiple drivers. Without directions two modules can drive one signal and produce x; with a modport that becomes an error at compile time. You pick it in the receiving port declaration, not at the connection.
Lecture 3 · 10
Monitor
Testbench에서 인터페이스 신호를 읽어서 transaction으로 되돌리는 부품. DUT를 건드리지 않는 수동 부품이다. Checker와 Coverage는 Monitor 없이 붙을 수 없다. 관측을 안 하는데 판정하거나 셀 수 없기 때문이다. Driver가 없는 곳에도 붙일 수 있다.
The testbench component that reads interface signals back into transactions. It never touches the DUT and is passive. Neither a checker nor coverage can attach without one, because nothing can be judged or counted that was never observed. It can be placed where no driver exists.
Lecture 2 · 18
Multicycle Path
한 클럭 안에 끝나지 않아도 되는 timing path. 예를 들어 부팅 때 한 번 쓰고 안 바뀌는 configuration register에서 나오는 경로가 그렇다. Timing constraint로 선언하면 STA가 여러 클럭을 허용한다. 잘못 선언하면 진짜 위반이 조용히 무시되므로 리뷰 대상이다.
A timing path allowed more than one clock to settle, such as one starting from a configuration register written once at boot. Declaring it in the timing constraints makes STA allow the extra clocks. Declared wrongly it silently hides a real violation, so these get reviewed.

N

NBA
Non-Blocking Assignment
Verilog의 <= 대입. 시뮬레이터가 별도의 이벤트 큐에서 처리한다. Blocking 대입(=)과 같은 always 블록에서 섞어 쓰면 안 되는 이유가 이것이고, lint가 그것을 잡는다.
The <= assignment in Verilog. The simulator processes these from a separate event queue, which is why mixing them with blocking assignments (=) in one always block is a hazard, and why lint flags it.
Lecture 2 · 14
net · variable
IEEE 1800이 자료형을 나누는 두 갈래. net(wire, tri)은 여러 드라이버를 받고 충돌하면 언어 규칙으로 값을 결정한다. variable(logic, reg, int)은 드라이버가 하나여야 하고 마지막에 대입된 값을 들고 있는다. logic은 net이 아니라 variable이다. 이걸 알아야 왜 아직 wire가 필요한지가 읽힌다.
The two families IEEE 1800 splits types into. A net (wire, tri) accepts several drivers and resolves conflicts by language rules. A variable (logic, reg, int) takes one driver and holds the last value assigned. logic is a variable, not a net, and knowing that is what makes the surviving uses of wire make sense.
Lecture 3 · 02
Netlist
gate와 flip-flop이 wire로 연결된 목록. Synthesis가 RTL을 씹어서 뱉어내는 것이다. "무엇을 하고 싶은지"는 남지 않고 "어떤 부품이 어떻게 연결되는지"만 남는다. ECO가 손대는 대상이 바로 이것이다.
A list of gates and flip-flops joined by wires, produced when synthesis chews the RTL down. Nothing about intent survives, only which parts connect to which. It is the thing an ECO edits.

P

package
typedef, function, struct, class 같은 것을 이름 있는 상자에 담아두는 것. 바깥에서는 my_pkg::state_t로 지목하거나 import my_pkg::*;로 통째로 가져온다. Verilog의 전역 이름공간과 `include + `ifdef 조합을 대체한다. 매크로가 아니라 언어 기능이라 컴파일 순서에 안 휘둘린다.

It replaces Verilog's global namespace and the `include plus `ifdef dance. Being a language feature rather than a macro, it does not depend on compile order.
Lecture 3 · 11
packed · unpacked
배열 차원의 두 종류. packed는 변수 이름 왼쪽에 오고 비트들을 하나의 워드로 다룬다. unpacked는 이름 오른쪽에 오고 원소를 독립된 변수로 다룬다. logic [3:0] t[6];은 4비트짜리 원소 6개다. 접근은 순서가 뒤집혀서 t[원소][비트]로 쓴다. 설계에서는 각각 하나씩만 쓰는 것이 관행이다.
The two kinds of array dimension. Packed goes to the left of the name and treats the bits as one word; unpacked goes to the right and treats elements as independent variables. logic [3:0] t[6]; is six four-bit elements. Access reverses the order: t[element][bit]. Designs conventionally use one of each and no more.
Lecture 3 · 08
Pipelining
처리를 단계로 쪼개고 사이에 register를 넣어 throughput을 올리는 기법. 주의할 점은 timing과 performance가 다르다는 것이다. 파이프라인을 깊게 하면 각 단이 짧아져 timing은 좋아지지만 한 건의 지연은 오히려 늘어난다.
Splitting processing into stages with registers between them, raising throughput. Note that timing and performance are not the same thing: deepening a pipeline shortens each stage and improves timing while making the latency of a single item worse.
Lecture 2 · 10
PLL
Phase-Locked Loop
내부 오실레이터를 외부 reference 클럭에 피드백으로 고정시켜 주파수를 곱하거나 나누는 회로. 아날로그 설계자가 만들고 디지털 쪽은 IP로 받아 쓴다. DLL과 달리 오실레이터가 있어 주파수를 바꿀 수 있다.
A feedback loop that locks an internal oscillator to a reference clock and can multiply or divide the frequency. Built by analogue designers and dropped into digital designs as IP. Unlike a DLL it has an oscillator, so it can change frequency.
Lecture 4 · 02

R

RDC
Reset Domain Crossing
한 reset 도메인에서 비동기로 assert된 reset의 영향이 다른 reset 도메인의 register에서 샘플되는 경계. CDC와 이름이 대칭이고, 클럭이 같아도 reset만 다르면 생긴다.
A boundary where the effect of a reset asserted asynchronously in one reset domain ends up sampled by a register in a different reset domain. Deliberately symmetric with CDC in name; it can exist even on a single clock if the resets differ.
Lecture 4 · 11
Recovery Time
비동기 set/reset이 풀리는 순간과 다음 클럭 엣지 사이에 필요한 최소 시간. 위반의 성격은 setup/hold와 똑같지만, 대상이 데이터 경로가 아니라 reset release 타이밍이고 STA가 같은 방식으로 검사한다.
The minimum time between an asynchronous set or reset being released and the next clock edge. A violation behaves exactly like a setup/hold violation, except the subject is reset release timing, not a data path, and STA checks it the same way.
Lecture 4 · 10
ref
pass by reference
task나 function의 인자를 복사하지 않고 원본을 가리켜서 넘기는 것. 보통 output 인자는 task가 끝날 때 한 번 복사해 돌려주지만, ref는 바뀌는 즉시 바깥에 보인다. 슬라이드의 말풍선이 "All output updates seen", "Input changes detected"라고 적은 것이 이 뜻이다. 합성되지 않는다. testbench 문법이다.
Passing a task or function argument as a handle to the original rather than a copy. A plain output argument copies back once, when the task ends; a ref is visible outside the moment it changes. That is what the slide callouts mean by "All output updates seen" and "Input changes detected". It does not synthesise: this is testbench syntax.
Lecture 3 · 14
Reset Synchronizer
비동기 reset의 assert는 그대로 두고 de-assert만 목적지 클럭에 맞춰 내보내는 회로. Double-FF synchronizer와 회로 모양이 똑같지만, 통과시키는 게 데이터가 아니라 reset이라는 게 다르다.
A circuit that leaves the assertion alone and aligns only the de-assertion of an asynchronous reset to the destination clock. Drawn identically to a double-FF synchroniser, but what passes through it is a reset, not data.
Lecture 4 · 11
Retiming
회로의 기능을 바꾸지 않고 register의 위치를 옮겨 단 사이 지연을 고르게 만드는 최적화. Timing 목표에 대응하는 수단이다.
An optimisation that moves registers without changing what the circuit does, evening out the delay per stage. It is a lever for the timing goal.
Lecture 2 · 10
RTL
Register Transfer Level
매 클럭마다 데이터가 어느 register에서 어느 register로 옮겨가는지로 하드웨어를 기술하는 방식. 언어 이름이 아니라 추상화 수준이다. Verilog와 VHDL이 언어고, 같은 언어로 더 추상적으로도 더 구체적으로도 쓸 수 있다. Behavioral과 structural 사이에 있는 실용적 타협점이다.
Describing hardware by which register the data moves to, on each clock. It is a level of abstraction, not the name of a language. Verilog and VHDL are the languages, and either can be written more abstractly or more concretely. RTL is the practical compromise between behavioral and structural.

Rule of 10
버그를 찾는 단계가 한 칸 늦어질 때마다 비용이 10배가 된다는 경험칙. Design 1, Wafer 10, Chip 100, System 1000, Application 10000. 발표자 노트가 구체적 사례를 적어놨다: Intel 프로세서의 부동소수점 유닛 버그가 약 10억 달러를 물렸다.
The rule of thumb that each stage later costs ten times more to find a bug: 1 at design, 10 at wafer, 100 at chip, 1000 at system, 10000 at the application. The speaker notes give the concrete case: the floating point bug in Intel processors cost around a billion dollars.

SAT
Satisfiability
Boolean 함수를 참으로 만들 수 있는지 확인하는 문제. CNF(=POS) 형태로 바꾼 뒤 만족하는 대입을 찾는다. 하나라도 있으면 satisfiable, 하나도 없으면 unsatisfiable. BDD와 마찬가지로 조합 논리에만 적용된다.
The question of whether a boolean function can ever be true. Convert it to CNF, also called product of sums, and look for a satisfying assignment. One is enough to call it satisfiable; none makes it unsatisfiable. Like BDDs, it applies only to combinational logic.

Scan Chain
DFT의 대표 장치. 설계 안의 flip-flop들을 사슬처럼 이어두고, 그 사슬로 내부 값을 밖으로 밀어내거나 안으로 밀어넣는다. 목적은 제조된 칩에서 핀만으로 안을 들여다보는 것이다. 대가는 flip-flop마다 mux가 붙어 면적이 늘고 경로가 길어지는 것이다. 넣는 시점은 설계 때지만 쓰는 곳은 Testing이다.
The signature DFT structure: the flip-flops of a design are strung together in a chain so values can be shifted out of, or into, the chip through it. The purpose is seeing inside a manufactured part using only its pins. The price is a mux on every flip-flop, adding area and lengthening paths. Inserted at design time, used in testing.

Slack
여유 시간. 신호가 도착해야 하는 시각에서 실제로 도착한 시각을 뺀 값이다. 양수면 통과, 음수면 위반이고 음수 slack을 timing violation이라고 부른다. 합성과 STA 리포트의 핵심 숫자이며, "worst negative slack이 얼마냐"가 곧 "이 설계가 얼마나 안 되고 있냐"다.

STA
Static Timing Analysis
모든 timing path를 분석해 회로의 타이밍 성능을 검증하는 방법. "static"인 이유는 입력 벡터가 관여하지 않기 때문이다. 값을 흘려보지 않고 경로 지연만 더해서 판단하므로 빠르고 빠짐없지만, 그 경로가 실제로 쓰이는지는 모른다. 그래서 false path와 multicycle path를 사람이 알려줘야 한다. Path는 네 종류: PI to Flop, Flop to Flop, Flop to PO, PI to PO.
Validating a circuit's timing by analysing every timing path. It is static because no input vectors are involved: it adds path delays rather than pushing values through, which makes it fast and exhaustive but blind to whether a path is ever used. Hence false paths and multicycle paths have to be declared by a human. Four kinds of path: PI to flop, flop to flop, flop to PO, PI to PO.

DC's file lookup path and startup script. .synopsys_dc.setup exists under the same name in three places, executed in order: $SYNOPSYS/admin/setup (tool defaults), then ~user (personal), then CWD (project-specific, and last, so it overrides the other two). That is what lets each project point at a different library while the design scripts stay put. Write relative paths in search_path; absolute ones break in anyone else's environment. Not the same file as the simulator's synopsys_sim.setup.

Stimulus
DUT를 자극하려고 넣는 입력. Active는 값을 밀어 넣는 것, Reactive는 DUT에서 벌어진 일에 반응하는 것이다. 검증의 세 기둥 중 하나이고, 이것만 있으면 시뮬레이션이 항상 통과한다. 결과를 보는 사람이 없기 때문이다.

struct
관련된 신호를 한 덩어리로 묶는 자료형. module 안에서도 쓰고 포트에도 쓴다. 포트 하나가 여러 필드를 통째로 나르므로 필드를 하나 추가할 때 포트 목록을 전부 고칠 필요가 없다. packed를 붙이면 빈틈없는 비트 벡터가 되어 통째로 시프트하거나 FIFO에 실어 보낼 수 있다. 대신 모든 필드가 integral type이어야 한다.
A type that groups related signals. Usable inside a module and on its ports, so one port carries many fields and adding a field does not mean editing every port list. Synthesis

SystemVerilog

task · function
구별 기준은 하나다: 시간을 쓰는가. function은 #, wait, @를 못 쓰고 호출한 시점에 즉시 끝나며 그래서 조합 논리로 합성된다. task는 여러 클럭에 걸쳐 돌 수 있고 그래서 대개 합성되지 않는다. SystemVerilog가 function에 return과 output 인자를 추가했다.

Lecture 2 · 18
Tristate
출력이 세 가지 상태를 갖는 것. 0, 1, 그리고 z(아무것도 안 몲, high impedance). z로 물러날 수 있어야 다른 드라이버가 그 선을 가져갈 수 있다. 약속이 깨져 두 드라이버가 동시에 몰면 시뮬레이션에서는 x지만 실물에서는 전류와 열이다. 그래서 칩 내부는 대부분 mux로 대체됐고 tristate는 양방향 IO 패드에 주로 남아 있다.
An output with three states: 0, 1, and z, driving nothing, high impedance. Being able to fall back to z is what lets another driver take the line. When the agreement breaks and two drive at once, simulation shows x and silicon burns current. On-chip tristate has therefore largely been replaced by muxes, surviving mostly at bidirectional IO pads.

Unsized Literal
폭을 안 적은 리터럴. SystemVerilog의 '0 '1 'x 'z는 대상 신호의 폭을 알고 그 값 하나로 전체를 채운다. 6'b1은 숫자 1이지만 '1은 전부 1이다. 그리고 폭이 모자란 리터럴은 위쪽이 0으로 채워지므로 4'bx를 6비트에 넣으면 00xxxx가 된다. 리셋 값 쓸 때 매번 쓰게 된다.

UVM
Universal Verification Methodology
검증 방법론의 사실상 표준. 언어가 아니라 SystemVerilog로 쓰인 class 라이브러리 + 관행의 묶음이다. testbench 부품의 이름과 모양과 붙이는 방법을 정해두어 남이 만든 것(VIP)을 가져다 쓸 수 있게 한다. VMM과 OVM을 합친 것이다. 이 과목에서는 Lecture 15~22와 Lab 6에서 다룬다.
The de facto standard verification methodology. Not a language but a class library written in SystemVerilog, plus a set of conventions. By fixing the names, shapes and connection rules of testbench components it makes it possible to use what somebody else built, that is, VIP. It merged VMM and OVM. This course covers it in lectures 20 to 22 and Lab 6.
Lecture 2 · 22

V

Validation
"살아 있는" 실리콘에서 하는 일. manufacturing test를 통과한 물건으로 한다. EVB를 만들고, 간단한 기능 확인부터 시작해 OS를 부팅하고 실제 테스트나 벤치마크를 돌리고, 전력과 전기적 특성을 실측한다. 순서상 Testing 다음이다. 제조 결함이 있는 칩으로 OS를 부팅해봐야 뭐가 문제인지 알 수 없기 때문이다.
The work done on silicon that is already alive, meaning parts that passed manufacturing test. You build an EVB, start with simple functional checks, go as far as booting an OS and running real benchmarks, and measure power and electrical characteristics for real. It comes after testing, because booting an OS on a defective part tells you nothing about where the problem is.

VCS
Verilog Compiler Simulator
Synopsys 의 시뮬레이터. 설계를 실행 가능한 프로그램(simv)으로 바꿔서 돌린다. 순수 Verilog / SystemVerilog 면 vcs 와 simv 두 번으로 끝나고(2-step), VHDL 이나 SystemC 가 섞이면 앞에 analysis 가 붙어 세 번이 된다(3-step). 갈리는 이유는 VHDL 이 bottom-up 으로 분석해야 하는 언어이기 때문이다.
Synopsys's simulator. It turns a design into an executable program (simv) and runs it. For pure Verilog or SystemVerilog it is two commands, vcs then simv; mix in VHDL or SystemC and an analysis stage appears in front, making three. The split exists because VHDL has to be analysed bottom up.
Lab 0 · 03
Verdi
Synopsys 의 디버그 도구. 파형 뷰어라고만 알면 절반만 아는 것이다. KDB 와 FSDB 를 겹쳐 읽어서 파형의 한 지점을 소스의 한 줄에 연결하고, 신호를 거슬러 원인까지 추적한다. 예전에는 시뮬레이터와 디버거가 달라 같은 설계를 두 번 컴파일했는데, Unified Front-End 가 그것을 -kdb 하나로 없앴다.
Synopsys's debug tool. Calling it a waveform viewer is half the story. It reads KDB and FSDB together to tie a point on a waveform to a line of source, and traces signals back to a cause. Simulator and debugger used to be separate tools, so the same design got compiled twice; the Unified Front-End collapsed that into a single -kdb.
Lab 0 · 07
Verification
설계가 사양을 올바르게 구현했는지 확인하는 일. 제조 전에 하고, 한 번만 하고, 설계 파일을 들고 있으므로 모든 내부 노드를 보고 조작할 수 있다. 잡는 것은 설계 버그이고, 설계의 품질을 책임진다. 설계 노력의 50~80%를 차지하며, 설계자 1명당 검증자 3~5명이 붙는다.
Checking that the design correctly implements the specification. It happens before manufacturing, once, and since you hold the design files every internal node is visible and drivable. It catches design bugs and owns the quality of the design. It takes 50 to 80 percent of design effort, with three to five verification engineers per design engineer.

Verification Plan
DUT를 어떻게 검증할 것인지를 적은 문서. 전략, 방법론, testbench 구성 요소, sign-off 기준, 그리고 기능 목록이 들어간다. 기능마다 stimulus·checking·coverage 세 줄을 적는데, 그게 곧 검증의 삼각대다. 형식은 Word, Excel, Synopsys HVP, Cadence VPlan 등.
A document describing how you will verify a DUT: strategy, methodology, testbench components, sign-off metrics and a list of features. Each feature gets three lines, stimulus, checking and coverage, which is the trifecta itself. Formats include Word, Excel, Synopsys HVP and Cadence VPlan.
Lecture 2 · 20
VIP
Verification IP
재사용 가능한 검증 자산. 예를 들어 EDA 벤더에게서 checker나 agent를 사서 우리 testbench에 끼워 넣는다. 이게 가능하려면 부품의 모양이 표준화돼 있어야 하고, 그래서 UVM 같은 방법론이 필요하다.
A reusable verification asset: buy a checker or an agent from an EDA vendor and plug it into your testbench. That only works if component shapes are standardised, which is what a methodology such as UVM is for.
Lecture 2 · 22

W

Wrap Bit
FIFO 포인터에서 주소로 쓰이지 않는 맨 위 한 비트. 주소부가 한 바퀴 돌 때마다 저절로 뒤집혀서 "몇 바퀴째인가" 를 기록한다. 이것 덕분에 두 포인터가 같은 주소에 있을 때 전부 같으면 empty, wrap bit 만 다르면 full 로 가를 수 있다. 주소가 ADDR_WIDTH 비트면 포인터는 ADDR_WIDTH+1 비트다. 슬라이드는 이 비트를 숫자로만 보여주고 이름을 붙이지 않는다. 업계에서 쓰는 이름이다.
The top bit of a FIFO pointer that is never used as an address. It flips by itself each time the address part wraps, so it records which lap you are on. That is what lets two pointers sitting on the same address be told apart: all bits equal means empty, wrap bits differing means full. If the address is ADDR_WIDTH bits, the pointer is ADDR_WIDTH+1. The slides only ever show it as a number and never name it; this is the industry name.

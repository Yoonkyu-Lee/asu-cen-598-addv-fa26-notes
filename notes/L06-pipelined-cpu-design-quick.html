결론부터

The short version

Pipelining 은 명령어를 다섯 단계로 쪼개고 서로 다른 명령어를 동시에 올리는 것이다. 강의 표현으로 temporal parallelism. 개념은 슬라이드 한 장이면 끝난다. 그런데 이 강의는 50 쪽이다. 나머지가 전부 쪼갠 대가를 치르는 이야기다.

Pipelining means cutting an instruction into five stages and letting different instructions occupy them at once. The lecture calls it temporal parallelism. The idea fits on one slide. The deck is 50. All the rest is paying for the cut.

슬라이드 27쪽의 한 문장이 이 강의 전체의 태도다. There is always a work-around but it always has a trade-off that you need to assess. 해법마다 무엇을 내주는지가 이 강의의 진짜 내용이다.

One sentence on slide 27 sets the tone for everything: There is always a work-around but it always has a trade-off that you need to assess. What each fix gives up is the real content of the lecture.

2

왜 쪼개나

Why split it up

Single cycle CPU 는 명령어 하나를 한 클럭에 끝낸다. 읽기는 전부 조합 회로라 (instruction memory, register file, data memory 모두 읽기는 clock 과 무관하다) 정말로 한 사이클 안에 다 들어간다. 문제는 셋이다.

A single cycle CPU finishes one instruction per clock. Every read is combinational (instruction memory, register file and data memory are all unclocked on reads), so it genuinely fits. Three things are wrong with it.

성능

Performance

클럭이 가장 긴 명령어에 맞춰진다. add 가 lw 를 기다린다

The clock follows the longest instruction. add waits for lw

전력

Power

모든 요소가 항상 켜져 있다. clock gating 이 불가능하다

Everything is always on. No clock gating possible

면적

Area

ALU 가 주기의 일부만 일하고 논다. 활용률이 낮다

The ALU works for part of the period and idles. Poor utilisation

슬라이드 16쪽의 숫자. 단계 지연이 100, 50, 100, 100, 50 ns 면 파이프라인 없이는 400 ns, 파이프라인은 가장 느린 단계인 100 ns. speedup 은 4 배다. 단계가 다섯인데 5 배가 아닌 이유는 50 짜리 두 단계가 100 을 배정받고 절반을 놀기 때문이다.

The numbers from slide 16. With stage delays of 100, 50, 100, 100, 50 ns, unpipelined is 400 ns and pipelined is 100 ns, the slowest stage. Speedup 4. Five stages, not five times, because the two 50 ns stages sit in a 100 ns slot and idle through half of it.

3

공짜가 아니다

What it costs

슬라이드 17쪽이 묻는다. 단수를 계속 늘리면 클럭을 계속 올릴 수 있나? 답은 두 식의 비대칭에 있다. G 는 게이트 수, T 는 조합 지연, R 은 register 비용, S 는 register 지연이다.

Slide 17 asks: can you keep adding stages to keep raising the clock? The answer is in the asymmetry between two formulas. G is gate count, T combinational delay, R register cost, S register delay.

파이프라인 없음unpipelined k 단k stages
costG + RG + R × k
throughput1 / (T + S)1 / (T/k + S)

비용은 k 에 정직하게 비례해 늘고, throughput 은 상한에 막힌다. T/k 는 0 으로 가지만 S 는 안 줄어들고, 조합 논리는 게이트 하나 밑으로 못 쪼갠다. 그래서 상한이 1 / (1 게이트 지연 + S) 다. 돈은 계속 내는데 성능은 안 오르는 구간이 생긴다.

Cost grows honestly with k while throughput hits a ceiling. T/k goes to zero but S does not shrink, and combinational logic cannot be split below one gate. Hence the cap at 1 / (1 gate delay + S). You reach a region where you keep paying and stop gaining.

슬라이드가 든 나머지 대가. 명령어 latency 증가 (특히 단계가 불균형할 때), hazard 를 해결하는 하드웨어 복잡도, 면적 증가, 전력 증가. 이 중 세 번째가 이 강의의 나머지 스무 장이다.

The other costs the slide lists: instruction latency goes up (especially with unbalanced stages), hardware complexity to resolve hazards, more area, more power. The third of those is the remaining twenty slides.

4

Hazard 세 종류

Three kinds of hazard

Hazard 는 앞선 명령어에 대한 의존 때문에 어떤 명령어가 진행하지 못하는 상황이다. 파이프라인이면 반드시 생긴다. 버그가 아니라 구조적 성질이고, 버그는 hazard 를 안 막은 쪽이다.

A hazard is when an instruction cannot make progress because it depends on an earlier one. Pipelines have them by construction. The hazard is not the bug. Failing to handle it is.

종류Kind 무엇이 부족한가What is missing 해법Fix
Structural 자원. 포트가 모자라거나 유닛이 파이프라인이 안 돼 있다a resource. too few ports, or a unit that is not pipelined 하드웨어 복제, 포트 증설, 아니면 한쪽 stallduplicate hardware, add ports, or stall one side
Data 값. 앞 명령어의 결과가 아직 register file 에 없다a value. the earlier result is not in the register file yet forwarding, stall, 또는 컴파일 타임 재배치forwarding, stalling, or reordering at compile time
Control 방향. 다음에 어느 명령어를 가져올지 모른다a direction. you do not know which instruction comes next flush, 판정 앞당기기, branch predictionflush, resolve earlier, branch prediction

Stall 과 flush 는 다르다. 둘 다 파이프라인에 구멍을 내지만 이유가 반대다.

Stall and flush are different. Both put bubbles in, for opposite reasons.

  • Stall 은 명령어를 제자리에 붙들어 둔다. 기다리면 쓸 수 있는 값이 오기 때문이다. data, structural
  • Stall holds an instruction in place, because waiting makes the value available. Data and structural
  • Flush 는 이미 들어온 명령어를 지운다. 애초에 실행되면 안 되는 것이었기 때문이다. control
  • Flush discards an instruction already inside, because it should never have run. Control

둘이 같이 가기도 한다. StallF = StallD = FlushE. 앞을 멈추면 EX 에 직전 명령어가 남아 두 번 실행되므로 그 자리를 지워야 한다.

They also travel together: StallF = StallD = FlushE. Holding the front leaves the previous instruction sitting in EX, where it would execute twice, so that slot gets erased.

5

Forwarding 과 stall

Forwarding and stalling

핵심 관찰 한 줄. add 의 결과는 EX 끝에 이미 존재한다. register file 에 적히는 것이 5 사이클째일 뿐이다. 그러면 보관소를 거치지 말고 바로 건네주면 된다. 그게 forwarding 이고, 회사에 따라 bypassing 이라 부른다.

One observation. The result of add already exists at the end of EX. Cycle 5 is only when it gets filed. So hand it over directly and skip the filing. That is forwarding, also called bypassing depending on where you work.

슬라이드 35쪽의 조건식. EX 로 받아오는 곳은 Memory 단계와 Writeback 단계 둘이다.

The condition on slide 35. Into EX, the value can come from the Memory stage or the Writeback stage.

if      ((rsE != 0) AND (rsE == WriteRegM) AND RegWriteM)  ForwardAE = 10   // Memory 에서
else if ((rsE != 0) AND (rsE == WriteRegW) AND RegWriteW)  ForwardAE = 01   // Writeback 에서
else                                                     ForwardAE = 00   // register file 에서
if      ((rsE != 0) AND (rsE == WriteRegM) AND RegWriteM)  ForwardAE = 10   // from Memory
else if ((rsE != 0) AND (rsE == WriteRegW) AND RegWriteW)  ForwardAE = 01   // from Writeback
else                                                     ForwardAE = 00   // from the register file

짧은 식에 세 가지가 들어 있다.

Three things hide in that short expression.

  • rsE != 0 · MIPS 의 $0 는 항상 0 으로 고정이라 forwarding 하면 0 이어야 할 값이 0 이 아니게 된다
  • rsE != 0 · $0 is hardwired to zero in MIPS, so forwarding into it would make a value that must be zero not zero
  • RegWriteM · 그 명령어가 실제로 register 를 쓰는지 확인한다. sw 의 destination 필드는 쓰레기다
  • RegWriteM · checks the instruction actually writes a register. The destination field of an sw is garbage
  • M 을 W 보다 먼저 본다 · else if 라 Memory 가 이긴다. 더 최근 명령어의 값이 맞기 때문이다. 순서를 뒤집으면 조용히 틀린다
  • M is tested before W · the else if makes Memory win, because the more recent instruction is the right one. Flip it and you silently use a stale value

lw 바로 뒤는 forwarding 으로 안 된다. 이 강의에서 제일 중요한 함정이다.

A use right after an lw cannot be forwarded. The most important trap here.

lw  $s0, 40($0)
and $t0, $s0, $s1

이유는 타이밍이 아니라 물리다. lw 의 값은 메모리를 읽어야 나오므로 MEM 끝에야 존재하는데 and 는 같은 사이클의 EX 에서 원한다. 없는 값은 못 당겨온다. 한 사이클 stall 하고 그 다음에 forwarding 한다. 조건식은 lwstall = ((rsD == rtE) OR (rtD == rtE)) AND MemtoRegE 다.

The reason is physics, not bookkeeping. The load value only exists at the end of MEM because memory must be read, and and wants it in EX in that same cycle. You cannot forward what does not exist. Stall one cycle, then forward. The condition is lwstall = ((rsD == rtE) OR (rtD == rtE)) AND MemtoRegE.

이 패턴을 load-use hazard 라고 부른다. 슬라이드에는 그 이름이 없지만 표준 표현이다.

The pattern is called a load-use hazard. The slide does not name it, but that is the standard term.

6

분기가 제일 비싸다

Branches are the expensive ones

Data hazard 는 값이 없는 문제였다. Control hazard 는 어느 명령어를 가져와야 하는지 자체를 모르는 문제라 더 나쁘다.

A data hazard is a missing value. A control hazard is not knowing which instruction to fetch at all, which is worse.

하나를 고치면 다른 게 생긴다. 슬라이드 43쪽이 직접 말한다. Introduced another data hazard in Decode stage. 분기 피연산자가 바로 앞 명령어의 결과면 그 값이 아직 없다. 해법은 같은 도구를 다시 쓰는 것이다. 쓸 수 있으면 forwarding, 아니면 stall. 파이프라인 설계는 대가를 옮길 수는 있어도 없앨 수는 없다.

Fixing one thing creates another. Slide 43 says it: Introduced another data hazard in Decode stage. If a branch operand came from the instruction right before, it is not there yet. The fix is the same toolbox again: forward if you can, stall if you cannot. In pipeline design you can move the cost around, not delete it.

마지막 수단이 branch prediction 이다. 판정을 기다리지 않고 찍는다.

The last move is branch prediction: guess instead of waiting.

  • Static · 방향만 본다. 뒤로 가는 분기면 taken (루프일 가능성이 높다), 앞으로 가면 not taken
  • Static · direction only. Backward means taken, since it is probably a loop. Forward means not taken
  • Dynamic · 최근 수백 개의 분기 이력을 branch target buffer 에 기록한다. 목적지와 taken 여부 둘을 담는다
  • Dynamic · keeps the last several hundred branches in a branch target buffer, recording the destination and whether it was taken

슬라이드의 정리가 정확하다. Good prediction reduces fraction of branches requiring a flush. flush 를 없애는 게 아니라 비율을 줄인다.

The slide's summary is exact: Good prediction reduces fraction of branches requiring a flush. Not removing flushes, reducing the fraction.

시험에 나올 것

What shows up on the quiz

quiz 가 객관식이라 둘 다 맞는 말처럼 보이는 짝이 나온다. 이 강의의 다섯 짝.

계산 문제라면 슬라이드 16쪽의 speedup 이다. 함정은 단계 수로 나누고 싶어지는 것이고, 분모는 가장 느린 단계다.

For a calculation it will be the speedup from slide 16. The trap is wanting to divide by the stage count, when the denominator is the slowest stage.

# CLAUDE.md 카브 설계

2026-09-11

## 무엇을 왜

`CLAUDE.md` 가 34,719 자다. 이건 **매 세션 통째로 컨텍스트에 들어간다.**
섹션을 "매 세션 필요한 계약" 과 "그 작업을 할 때만 필요한 절차" 로 갈라 재보면 이렇다.

| | 분량 | 비중 |
|---|---|---|
| 계약 | 4,601 자 | 13% |
| 절차 | 30,118 자 | **86%** |

**세션에 들어가는 것의 7 분의 6 이 지금 하지 않는 작업의 절차다.**
노트를 안 쓰는 세션에도 `.jargon` 다섯 줄 규칙과 다크모드 팔레트가 전부 실린다.

절차를 스킬로 내리고 계약만 남긴다. 목표는 **세션당 컨텍스트 비용** 이다.

### 제약

1. **컨텍스트가 전혀 없는 에이전트가 기존 활동을 끝까지 할 수 있어야 한다.**
   노트 작성부터 GitHub Pages 발행까지.
2. **서브에이전트에 위임할 수 있어야 한다.** 대화 맥락 없이 스킬만 읽고 착수하는 경우가 기본이다.
   그래서 **스킬은 자족적이어야 하고, 혼자 못 끝내는 작업은 어떤 스킬이 더 필요한지 자기가 밝혀야 한다.**
3. **중복을 만들지 않는다.** 같은 내용이 두 곳에 길게 있으면 갈라진다. 기존 규칙을 유지한다.

## 최종 구조

### `CLAUDE.md` (~5,500 자 목표)

```
## 이 저장소가 하는 일        유지
## 착수 — 스킬 라우터          확장. 작업 → 스킬, 그리고 스킬 조합
## 경로                        압축. 브라우저 바이너리 경로 포함
## 브라우저 고르기             8 줄 결정표만. 운용 상세는 스킬로
## 절대 어기지 않는 것          신규. 불변식
## 커밋하는 것과 안 하는 것     압축. 저작권 결정은 그대로 유지
```

**불변식에 넣을 것.** 스킬을 안 읽고 들어가도 사고가 나지 않아야 하는 것만.

- 교재가 없다. 없는 교재를 적지 않는다
- **용어를 지어내지 않는다.** 이 과목의 최대 위험이고 자동 검사가 못 잡는다
- em dash 금지
- 업계 용어는 영어 유지, 서술은 한국어
- 의미 고정 색상 7 줄 표
- Drive 원본은 읽기 전용
- 커밋 금지 목록 (Lab 코드, quiz, pptx)

판단 기준은 **"어겼을 때 되돌리기가 비싼가"** 다. 절차는 다시 하면 되지만
용어를 지어내 배포한 노트는 사용자가 그걸 외운 뒤에 발견된다.

### 스킬

| 스킬 | 맡는 것 | 상태 |
|---|---|---|
| `write-note` | 노트를 **쓴다** | 확장 |
| `note-html` | 노트를 **만든다** (HTML 저작 규격) | 신규 |
| `convert-slides` | 슬라이드를 **넣는다** | 신규 |
| `synopsys-training` | gstack 으로 트레이닝 수집 | 유지 |
| `synopsys-training-chrome` | Chrome 으로 트레이닝 수집 | 유지 |

**`write-note` 와 `note-html` 을 가른 이유.** 기존 노트의 문구를 고칠 때는 HTML 규격만 필요하고
5 단 구조는 필요 없다. 합치면 카브 효과가 절반으로 준다.

### `docs/schedule.md`

30 강 모듈 표는 **스킬로 내리지 않는다.** 산문이 아니라 데이터고, 학기 중에 바뀌고,
`write-note` 와 `convert-slides` 양쪽이 본다. 한쪽에 넣으면 다른 쪽이 못 보고,
양쪽에 넣으면 갈라진다. **한 파일로 빼고 둘이 참조한다.**

## 자족성 장치

A 안의 유일한 실패 모드는 **"노트를 쓰려는데 `write-note` 만 읽고 HTML 규격을 모르는 것"** 이다.
각 스킬 맨 위에 의존 관계를 박아서 막는다.

```
**같이 필요한 스킬**: `note-html` (HTML 규격), `convert-slides` (슬라이드가 아직 없으면)
**단독으로 끝나는 것**: 기존 노트의 문구 수정
```

`CLAUDE.md` 라우터도 작업 단위로 조합을 적는다. "새 강의 노트" 는 세 스킬 전부다.

## 계약 문구 변경

지금: **"스킬과 이 문서가 어긋나면 이 문서가 이긴다."**

절차가 스킬로 내려가면 그 주제의 단일 출처는 스킬이 된다. 이 문장을 그대로 두면
카브된 내용에 대해 `CLAUDE.md` 가 이길 근거가 없는데도 이긴다고 주장하게 된다.

바꿀 문구: **"불변식은 이 문서가 이긴다. 각 절차의 단일 출처는 해당 스킬이다."**

## 검증

문서 카브는 자동 검사가 없다. **컨텍스트 없는 서브에이전트로 시험한다.**

카브 전에 먼저 돌려 기준선을 잡고, 카브 후에 같은 질문을 다시 던진다.
**카브 전에 답할 수 있던 것을 카브 후에도 답하면 통과다.**

1. "L05 노트를 새로 쓰려면 무엇을 어떤 순서로 하나" — 슬라이드 변환 → 앵커 → 검증 → `index.html` 갱신까지 나와야 한다
2. "이 저장소에서 커밋하면 안 되는 것은" — Lab 코드, quiz, pptx 가 나와야 한다
3. "노트에 새 도해를 넣을 때 색을 어떻게 고르나" — 의미 고정 색상이 나와야 한다

실패하면 스킬 내용이 아니라 **라우터와 의존 블록을 고친다.** 내용은 이미 옮겨져 있다.

`node scripts/verify.mjs` 는 이 작업의 영향을 받지 않는다. 노트 HTML 을 건드리지 않는다.

## 위험과 되돌리기

| 위험 | 대응 |
|---|---|
| 카브 중 내용 유실 | 섹션 단위로 옮기고 매핑표로 대조. 한 커밋에 하나씩 |
| 라우터가 스킬을 못 찾음 | 검증 3 문항이 이걸 잡는다 |
| 스킬이 길어져 결국 같은 비용 | 스킬은 필요할 때만 로드된다. 총량이 아니라 세션당 비용이 목표다 |

전부 문서 작업이라 `git revert` 로 되돌아간다. 노트 HTML 과 스크립트는 건드리지 않는다.

## 하지 않는 것

- 노트 HTML, `reader.js`, `scripts/` 의 코드 변경
- 규약 내용 자체의 변경. **옮기기만 한다.** 압축은 중복 제거 수준까지만
- 새 기능. 블로그는 기존 노트 발행을 가리키는 말이었고 새로 만들 것이 없다

# 실습 입문 페이지 (P 시리즈) 설계

2026-09-13. 승인된 설계를 옮긴 것이다. 구현 계획은 `docs/superpowers/plans/` 에 따로 둔다.

## 왜 만드는가

이 과목은 Verilog 를 안다는 전제로 진행된다. 그런데 이 사이트의 독자는 고수준 언어를 조금 써봤고
컴퓨터 구조를 조금 아는 사람까지 넓히려 한다. 그 독자가 3 강과 4 강을 읽으려면
**클럭이 무엇인지, flip-flop 이 무엇인지, comb / ff / latch 가 어떻게 다른지**를
글이 아니라 **손으로 밟아본 상태**여야 한다.

그래서 **강의 요약과 다른 장르**를 하나 더 둔다. 강의 번호를 따라가되, 단원마다
**"이 코드는 이 회로이고, 이렇게 돈다"** 를 보여주는 것이 전부다. 코드 · 회로 · 파형이 나란히 놓이고,
반 클럭 단위로 쪼갠 시뮬레이션을 시크바로 밟으면 셋이 같이 반응한다.
퀴즈가 아니다. 단원 제목의 "~라고 생각하기 쉽다" 는 독자가 흔히 갖고 들어오는 그림을 짚는
한 줄일 뿐이고, 본문은 코드 → 회로 → 동작 순서로 그냥 보여준다.

## 장르 규칙

| | 강의 노트 `L{NN}` | 실습 입문 `P{NN}` |
|---|---|---|
| 정렬 | 슬라이드 순서 | **"n 강을 읽기 전에 알아야 할 동작" 순서** |
| 단원 형식 | 정의 → 용어 → 도해 → 현장 감각 → 함정 | **코드 → 회로 → 밟아본다 → 한 줄 정리** 네 단 고정 |
| `data-slide` | 붙인다 | 안 붙인다 |
| `reader.js` | 넣는다 | 안 넣는다. 대신 `sim.js` |
| 마지막 절 | 정리 & 다음 강의 | **"n 강 어느 절로 가면 되나" 대응표** |

파일명은 `notes/P{NN}-{kebab}.html`. `{NN}` 은 그 페이지가 준비시키는 강의 번호다.
이번에 만드는 것은 `P03-before-lecture-3.html` 과 `P04-before-lecture-4.html` 둘이다.

## 단원 목록

### P03 · 3 강 전에 손에 익힐 것

| 단원 | 흔한 그림 | 시뮬레이션 | 보여주는 것 |
|---|---|---|---|
| 1 | "세 줄을 위에서 아래로 실행한다" | 없음. 정적 도해 2 장 (호출 스택 vs 전선) | 세 줄이 동시에 산다. instantiate ≠ call |
| 2 | "a 와 b 가 같이 바뀌면 y 도 바로 맞는 값이다" | `y = a & b`. a 와 b 가 다른 프레임에 도착 | y 가 한 프레임 틀린다. 회로에 "동시" 는 없다. 그래서 언제 읽을지 정하는 신호가 필요하다 |
| 3 | "d 가 바뀌면 q 도 바로 바뀐다" | `q <= d`. d 가 정착 프레임마다 바뀜 | q 는 엣지에서만. 한 칸 늦는 게 정상 |
| 4 | "셋 다 `q = d` 인데 셋 다 같은 회로다" | 같은 d 에 출력 셋: comb `y`, ff `q_ff`, latch `q_lat` (en = clk) | 즉시 / 엣지 / clk high 동안 투명 |
| 5 | "`q <= q + 1` 이면 q 가 무한히 커진다" | 2 비트 카운터 + `rst_n` | wrap 한다. reset 이 왜 필요한지 |
| 6 | "`=` 로 써도 `<=` 처럼 교환된다" | 두 flop 교환. 시뮬레이션 둘 나란히 | `<=` 는 교환, `=` 는 한쪽이 덮이고 회로에서 flop 하나가 사라진다 |
| 7 | "`else` 를 빼도 조합 논리다" | `if (sel) y = a;` else 없음 vs 있음. 둘 나란히 | 없으면 y 가 유지된다 = latch. 회로에 latch 상자가 생긴다 |
| 8 | 3 강 어느 절로 가면 되나 | 표 | 단원 ↔ L03 절 |

### P04 · 4 강 전에 손에 익힐 것

| 단원 | 흔한 그림 | 시뮬레이션 | 보여주는 것 |
|---|---|---|---|
| 1 | "엣지에 딱 맞춰 d 를 바꾸면 그 값이 잡힌다" | setup / hold 창 | 창 안에서 바뀌면 `X`. 창 밖이면 잡힌다 |
| 2 | "같은 clk 이니 두 flop 이 같은 순간에 잡는다" | skew. 둘째 flop 에 clk 이 늦게 도착 | 늦은 쪽이 새 값을 잡아버린다 (hold 위반) |
| 3 | "다른 클럭의 신호도 flop 에 넣으면 잡힌다" | clkA 신호를 clkB flop 이 엣지 근처에서 샘플 | `q1 = M` 한 프레임. 2 단째 `q2` 는 깨끗 |
| 4 | "reset 을 걸면 즉시 0 이 된다" | sync vs async reset. 둘 나란히 | sync 는 다음 엣지까지 기다린다. async 는 즉시 |
| 5 | "reset 을 풀면 즉시 정상이다" | async reset 이 엣지 근처에서 풀림 | `X`. recovery time |
| 6 | 4 강 어느 절로 가면 되나 | 표 | 단원 ↔ L04 절 |

P04 는 P03 의 3 · 4 단원을 안다고 가정한다. 첫 절에서 그렇게 밝히고 링크한다.

## 시뮬레이션 카드 (`.sim`)

```
┌ 코드 ──────────────┐ ┌ 회로 ──────────────┐
│ always_ff @(posedge)│ │  d ──▶[D  Q]──▶ q   │
│   q <= d;        ◀──┼─┼──────  ▲            │
└─────────────────────┘ └─────────────────────┘
┌ 파형 ──────────────────────────────────────┐
│ clk  ‾|_|‾|_|‾|_        │ (세로 커서)        │
│ d    ___‾‾‾‾___         │                   │
│ q    _____‾‾‾‾‾         │                   │
└─────────────────────────────────────────────┘
  |◀  ◀  [━━━━━●━━━━━━]  ▶  ▶|   ▶ 재생      cycle 3 · 엣지 직후
  "엣지가 왔다. d 가 1 이었으므로 q 가 지금 1 로 바뀐다."
```

- **프레임 단위는 반 클럭.** 프레임 `2k` = k 번째 posedge **직후** (flop 이 방금 잡은 상태, `clk=1`).
  프레임 `2k+1` = **정착** (comb 가 따라온 뒤, `clk=0`). 입력이 바뀌는 건 정착 프레임에서만.
- **강조 규칙.** 이번 프레임에 값이 바뀐 신호 → 배선 굵게, 파형 그 칸에 배경, 그 신호를 모는 코드 줄에 왼쪽 바.
  엣지 프레임에서는 flop 박스가 한 번 깜빡인다.
- **색.** 논리 · 배선 `--blue`, 클럭선 `--brown`, `X` · `M` · latch 투명 구간 `--amber`, "잡혔다" `--green`.
  `CLAUDE.md` 의 의미 고정 색상 그대로.
- **조작.** 처음 / 이전 / 시크바 / 다음 / 끝, 재생 · 일시정지 (프레임당 700 ms), 키보드 ← →.
  현재 프레임 라벨과 프레임 해설 (이중 언어).
- 900 px 아래에서 코드 · 회로가 세로로 쌓인다. 파형은 가로 스크롤.
- 상태는 JS 변수. 브라우저 저장소를 쓰지 않는다.

## 시나리오 데이터

페이지 안 `<script type="application/json" id="sim-data">` 에 시나리오 배열을 둔다.
`sim.js` 와 `simcheck.mjs` 가 **같은 JSON 을 읽는다.**

```js
{ "id": "p03-ff",
  "title": { "ko": "…", "en": "…" },
  "code":    [ { "t": "always_ff @(posedge clk)" },
               { "t": "  q <= d;", "drives": ["q"] } ],
  "circuit": { "w": 320, "h": 120,
               "nodes": [ { "id": "f1", "kind": "ff", "x": 140, "y": 40, "in": { "d": "d", "clk": "clk" }, "out": { "q": "q" } } ],
               "ports": [ { "sig": "d", "side": "in",  "y": 60 },
                          { "sig": "q", "side": "out", "y": 60 },
                          { "sig": "clk", "side": "in", "y": 100 } ],
               "wires": [ { "sig": "d",   "pts": [[20,60],[140,60]] },
                          { "sig": "q",   "pts": [[200,60],[300,60]] },
                          { "sig": "clk", "pts": [[20,100],[170,100],[170,80]] } ] },
  "signals": [ { "n": "clk", "kind": "clk" }, { "n": "d" }, { "n": "q" } ],
  "frames":  [ { "v": { "clk": 1, "d": 0, "q": 0 }, "note": { "ko": "…", "en": "…" } } ] }
```

- 노드 종류: `ff`, `latch`, `and`, `or`, `not`, `xor`, `mux`, `add`, `const`. 격자 위 박스. 핀 위치는 종류가 정한다.
  `in` / `out` 은 핀 이름 → 신호 이름. 검사기가 이걸로 의미를 재계산한다.
- 배선은 직교 꺾은선을 직접 적는다. `sig` 로 값과 강조를 묶는다.
- 값은 `0` / `1` / 정수 (버스, `signals[].bits` 로 폭) / `"X"` / `"M"` (metastable).
  파형은 프레임 배열에서 자동으로 그린다. 손으로 그리는 파형은 없다.
- `frames` 길이는 짝수. 첫 프레임은 엣지 프레임.

## `sim.js` (루트, `reader.js` 옆)

인라인 규칙의 **두 번째 예외**다. `note-html` 스킬에 이 사실을 적는다.
페이지는 `<script src="../sim.js" type="module"></script>` 한 줄만 넣는다.

- `document.querySelectorAll('.sim[data-sim]')` 마다 `#sim-data` 에서 시나리오를 찾아 붙인다.
- 렌더러 셋: `renderCode`, `renderCircuit`, `renderWave`. 각각 시나리오와 프레임 번호를 받아 DOM 을 만든다.
- 프레임 이동은 `go(i)` 하나. 세 렌더러가 `i` 만 보고 강조를 다시 칠한다.
- `langchange` 이벤트에서 해설과 라벨을 다시 그린다.
- 외부 의존성 없음. `reader.js` 와 마찬가지로 없어도 본문은 읽힌다 (카드에 "시뮬레이션을 못 불러왔다" 한 줄).

## `scripts/simcheck.mjs`

트레이스를 손으로 쓰니 틀릴 수 있다. HTML 에서 JSON 을 꺼내 **노드 종류의 의미대로 재계산해 대조**한다.

- `ff`: 엣지 프레임의 `q` = 직전 프레임의 `d`. 정착 프레임은 유지.
- `latch`: `en = 1` 인 프레임은 `q = d`. 아니면 유지.
- 게이트 · `mux` · `add`: 매 프레임 입력에서 출력 재계산.
- 값이 `"X"` 나 `"M"` 인 칸은 검사에서 제외한다 (P04 전용).
- 구조 검사: 프레임 수 짝수, 모든 신호가 모든 프레임에 값이 있는지, `drives` 와 `wires[].sig` 가 실제 신호인지,
  `clk` 신호가 엣지 프레임에서 1 · 정착 프레임에서 0 인지.

하나라도 어긋나면 exit 1. `verify.mjs` 처럼 파일 경로를 받는다.

## 검증

```bash
node scripts/simcheck.mjs notes/P03-before-lecture-3.html
node scripts/verify.mjs   notes/P03-before-lecture-3.html    # .sim 도 .play 처럼 스크린샷
node scripts/langcheck.mjs notes/P03-before-lecture-3.html
node .gstack/tmp/simstep.mjs notes/P03-before-lecture-3.html  # 시나리오마다 끝까지 밟고 콘솔 에러 0
```

`verify.mjs` 는 `.sim` 을 도해 스크린샷 대상에 넣도록 셀렉터 한 줄을 고친다.

## 허브와 연결

- `index.html` 헤더의 glossary 카드 옆에 **입문 카드** 하나. 두 페이지로 가는 링크 둘.
- `L03` · `L04` 노트 00 절에 "Verilog 를 한 번도 안 봤으면 여기부터" `.callout` 한 줄.
- `note-html` 스킬의 파일 명명 표에 `P{NN}` 행과 `sim.js` 행을 더한다.
